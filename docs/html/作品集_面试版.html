HR-Agent OS · 作品集（面试版）

一个能真跑起来的 B 端 HR AI Agent 平台。 界面上的每一个分数都能回答「为什么是这个分」，每一次越权都在服务端被 403 拦下， 每一份 JD 都会先对着真实在招市场校准、再做一遍用工合规扫描。 最关键的一句：这些结论全部可复现 —— 不接大模型也能跑通全流程。

一句话看懂它和「长得像 HR 系统的演示原型」的区别： 原型是「点得动」，这个项目是「答得上」。 答得上分数怎么来的、答得上越权为什么被拒、答得上 JD 为什么这么写。

一、我在解决什么问题

HR 场景里，AI 落地真正难的不是「接一个大模型」。我把痛点拆成三条，这个项目的每一处设计都对应其中一条：

#真实痛点为什么难本项目的解法
1AI 给的结论业务方不敢签字分数是黑盒，出了问题无法追溯分数与档位 100% 由确定性规则算出（可复现、可追溯）；分数下面常驻一栏「为什么是这个分」，逐维算式 + 决定性因素 + 还差几分进下一档
2HR 系统天生处理敏感数据权限写在页面上、数据早出了库，等于没权限权限在出数据之前生效：24 能力 × 7 角色 + 行级数据范围（all/dept/self）+ PII 字段物理脱敏；越权是真 403，前端按钮显隐只是体验层
3JD 里一句老措辞就是法律风险涉及年龄、性别或户籍的表述，写的人不觉得有问题，HR 也未必逐句审生成前先检索市场在招同类岗位做「接地」，生成后做合规扫描，命中就业歧视性表述（年龄／性别／户籍等）直接阻止发布，每条给法条依据 + 建议改法

目标用户：中大型企业 HR 部门 / 招聘团队（私有化、数据不出境）。

二、产品设计：三个「必须」与三个「不做」

必须为什么
必须可解释每个分数都要能摊开算给业务方看。归因只读打分时已算出的系数、不做二次计算，测试里锁死「分项之和 == 总分」
必须可复现同一份简历跑两次结果必须一致，否则不能拿去和业务方对齐
必须留痕应用层只插不改，外加数据库 BEFORE UPDATE / BEFORE DELETE 触发器 RAISE(ABORT) —— 想改审计得先改 schema，而 schema 是版本化迁移管的
不做为什么
不把判断权交给模型分数与档位全由确定性规则算出；模型只做三件事：推荐理由的措辞、制度问答的语言组织、JD 润色
不编硬数字页面上的成本/用量必须能指出来源。规则模式就是 0 调用、显示 0，不显示一个「看起来合理」的试算值冒充真实用量
不让 AI 越过人工闸门高风险动作（Offer 决策、推翻 AI 结论）必须留人工签批，AI 只负责把它推到闸门前面

三、五个核心能力（每条都写明「为什么它是真的」）

#能力为什么不是话术
1分数可解释分数下面有一栏「为什么是这个分」：逐维算式（技能匹配 40 × 0.95 = 38）+ 决定性因素 + 还差几分进下一档。测试锁死「分项之和 == 总分」「满分 × 系数 == 该维得分」
2规则与模型分工明确分档 100% 规则（可复现、可签字）；模型只做措辞与语言组织。「不配大模型也能跑通全流程」不是降级方案，是设计选择 —— 见双模式对照评测
3权限真的在服务端24 能力 × 7 角色 + 行级范围 + PII 脱敏，全部在出数据之前生效。员工身份导出全公司花名册是真 403（缺 employee:export 能力）
4审计改不掉应用层只插不改 + 数据库触发器 RAISE(ABORT)，审计日志无法被应用层篡改
5JD 接地真实市场 + 合规红线生成前按「标题优先」检索市场在招同类岗位（仓库自带 183 条抓取快照），拼接前做最长公共子串 + bigram 双去重；命中就业歧视性表述（年龄／性别／户籍等）这类表述直接阻止发布，每条给法条依据与建议改法

四、怎么证明它有效：一套自己搭的评测

AI 产品经理岗，面试官问的第一个技术问题通常是「你怎么衡量你的 AI 效果」。 所以我把评测做成了项目的核心交付物之一。

4.1 黄金集与口径

项内容
规模30 例（3 个岗位 × 各 10 例），人工标注、三档标签 strong / ok / no
判定顺序先过硬性门槛（年限 / 学历 / 技能相关性），再定档位 —— 顺序反了会把「技能很全但年限不够」标成优秀
证据来源标注时只看简历原文 + 岗位要求，禁止偷看算法输出（看一眼 = 把规则抄成答案 = 循环论证）
口径冻结rubricVersion = 1，写到代码里可机器校验（枚举合法 / id 唯一 / jobId 无悬空 / 每岗位 ≥10 例 / 每岗 ≥1 陷阱探针 / 三档占比 ∈[20%,50%]）
扩样方案独立成文（含 7 个必须先拍死的决策、三层难度配额、一致性验证），不拿规则输出当答案

4.2 三个指标（跟着一个红线）

指标当前值说明
档位一致率96.7%（29/30）严格三档一致
±1 档一致率100%从没出现「差两档」的离谱判断
漏筛率0.0%← 红线。HR 场景里「把好简历判死」的代价远高于「把差简历放进面试」，所以这个数必须守 0
误筛率8.3%12 个应拒样本里放了 1 个进来（宁可多聊一轮，不可错杀）
样本只有 30 例，所以我不敢只报点估计 —— 同时给出 Wilson 95% 置信区间 [83.3%, 99.4%]。 样本量不足是已知边界，扩样方案已独立成文，但不自己给自己标注（那是自证）。

4.3 一个真实的迭代

改「判定链条」而不是改「业务维度计数」，让一致率从 90.0% → 96.7%、误筛率 25.0% → 8.3%，同时保住漏筛 0%。

五个候选方案做了实测对照，选中的方案是唯一一个「一致率↑ 且 漏筛不↑」的。评测驱动的迭代，不是拍脑袋调阈值。

五、技术实现概览

维度选择为什么
运行时Node 22 原生 http + 内置 node:sqlite零依赖：clone 下来一条命令就能起，不需要装任何 npm 包。PoC 阶段把「环境问题」这个变量彻底消掉
前端单文件 HTML（内联全部 CSS/JS）断网可演示、双击即开。代价我主动说：没法按需加载、没有构建期校验
分层后端 16 个模块按 L0–L5 分层依赖方向单向，改一层不会牵连全栈
来源单一shared/ 三个文件是前后端共用数据源改一处，离线端与后端同时生效，避免两套逻辑漂移
数据库schema v9，版本化迁移空库自动迁移 + 种子，不提交任何数据文件
规模24 页面 / 47 接口 / 约 19,400 行 JS / 10,300+ 行文档全部由脚本从代码算出，写进文档的数字有守卫盯着（见第六节）

六、工程纪律：让「文档」不许撒谎

这一节是我认为最能体现工作方式的部分 —— 它不是"我写了文档"，是"我让文档没法骗人"。

机制做法挡住什么
回归套件12 个套件（后端 4 / 自包含 4 / 前端 4），一条命令全跑「改 A 坏 B」
文档真相守卫从代码读出 24 页面 / 47 接口 / 545,169 字节 / schema v9 等事实，去比对文档里的「现状句」文档与代码不一致（真发生过：四份文档四个页面数）
负向锚点不只钉住「现在是多少」，还禁止旧值复活修了一处、另外四篇还留着旧数字
评测基线单一源tools/golden/baseline.json 是评测数字的唯一源，守卫单向：质量 ≥ 基线、错误 ≤ 基线指标倒退还悄悄过 CI
生成物单一源全部阅读版 HTML 由一条命令从 Markdown 重生，清单在代码里「md 改了 HTML 还是旧的」
CINode 22 / 24 双矩阵 + Python 编译检查 + Pages 构建只在某一个 Node 版本上碰巧能跑
一条最典型的教训：我曾把评测基线写成四舍五入后的值，而守卫是单向往上比 —— 于是「真值 96.67% vs 基线 96.7%」被判成倒退，报了一个假红。 修法是把基线存原始值而不是显示值。教训写进了贡献指南。

7.2 三个真实翻过车的点（都留了回归用例）

翻车根因修法
「测试全绿」其实是假的前端套件把页面 id 写死成数组，新增页面时静默漏测，却照打「全部通过」改为从页面注册表派生，并由守卫禁止再写死
离线端与后端两套逻辑漂移同一个判定在两处实现，改了一处忘了另一处抽 shared/ 单一数据源；离线端必须镜像同一份词库与口径，改完跑对应套件
规则模式下却报了 token 与成本想让演示「看起来完整」，于是显示了一个凭空算出的金额违背自己定的「不编数字」原则 —— 改成规则模式一律显示 0，成本卡改「试算」并注明来源。一个 AI 产品如果连自己的成本数字都不可信，业务方不会信它的任何输出

八、我把自己当面试官，审了一遍自己的项目

这一节是我最想给面试官看的。我假装我是面试官，且我愿意翻代码，写了一份 12 项的缺口审计，按「面试杀伤力」而不是「修复难度」排序，并逐条记录修复状态。

被我自己抓出来、并且已经修掉的几条：

  • 筛选链路虚报模型调用与成本 —— 链路里其实 0 次模型调用，日志却记了模型工具名和 token 数。已修：工具名不撒谎，用量取自真实网关。
  • 「已进入优化数据集」是一句空话 —— 审计日志这么写，但数据集不存在。已修：改成真正可归因的原因码枚举 + 一致率接口。
  • 一个死按钮（演示复跑必经路径，点下去毫无反应）—— 已修，并补了后端接口。
  • WAL 从不 checkpoint —— 实测日志文件是主库的 11 倍且只增不减。已修，压测时顺手记录了 P95/P99。
  • 无障碍为 0 —— 政府采购评标普遍含无障碍要求。已补最小集（弹窗语义 / 焦点管理 / 表格表头 / 减少动效）。

为什么这一节值钱：绝大多数候选人展示的是「我做成了什么」。

我多展示一层 —— 「我知道它哪里还不行、并且我说得出来」。这恰好是这个岗位最重要的能力。

附：面试时我会主动讲的三句话

  1. 「分数和档位 100% 是规则算出来的，模型只负责措辞。」 —— 主动定义「AI 在哪一步」，别等面试官发现筛选链路默认没调模型。

  3. 「我知道它哪儿还不行 —— 这份自审清单就是证据。」 —— 把「不足」变成「我清楚边界」。
