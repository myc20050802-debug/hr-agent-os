## 零、先对齐一件事：「可以用」不是一个档位，是三个

**这是本文最重要的一句话：把「可用」和「企业级」混为一谈，是这类项目最常见、也最致命的误判。**

因为它会让你在最该上线的时候，去做换数据库、做多租户——结果永远没有「用起来」的那一天。

| 档 | 使用者 | 一句话验收标准 | 估算 |
|:--:|---|---|:--:|
| **A · 演示可达** | 面试官 / 售前听众 / 你自己 | 给他一个链接，他打开、登录、能完整点一遍 | **1–2 天** |
| **B · 团队可用** | 一个真实 HR 小组（3–10 人） | 每天拿**真简历**跑，重启不丢数据，出错有人知道 | **2–4 周** |
| **C · 对外可卖** | 付费客户（含私有化） | 两个客户数据不串、能过合规审查、能签 SLA | **2–6 月** |

**绝大多数人问「怎么变成能用的软件」时，真正想要的是 A 档，却按 C 档的清单在准备。** 本文先给 A 档的完整可执行路径。

## 一、现状盘点：缺的不是功能，是三件很具体的事

先说**已经有的**（这些是资产，不该被「离可用还差得远」这句话抹掉）：

| 能力 | 出处 | 状态 |
|---|---|:--:|
| 认证：不透明令牌 + 服务端 `sessions` 表、scrypt 哈希、防账号枚举（计时对齐）、5 次锁定、改密即踢下线 | `server/auth.js` | ✅ 生产级思路 |
| 权限：三层（能力 × 范围 × 字段），403 写审计 | `server/rbac.js` | ✅ |
| 审计：数据库触发器保证 append-only | `server/db.js` | ✅ |
| 迁移：版本化，空库可一键建到最新 | `server/migrations.js` | ✅ |
| 一键启动 / 一键回归 / 压测 / 评测集 | `package.json`、`tools/run_all.js` | ✅ |
| 运维：WAL checkpoint、优雅关闭、限流、安全头、路径穿越防护 | `server/http-kernel.js`、`server.js` | ✅ |
| 可观测：结构化日志 + 延迟分位 | `server/logger.js`、`server/metrics.js` | 有，但进程内 |

再说**真正卡住「可用」的**（按挡路程度排序）：

| # | 缺口 | 证据 | 卡住哪一档 |
|:-:|---|---|:--:|
| 1 | **绑死 `127.0.0.1`**，别人根本访问不到 | `config.js:77` `host: str('HOST','127.0.0.1')` | A |
| 2 | **无任何部署产物**：无 Dockerfile / CI / 反代配置 / `.env.example` | 全仓 Glob 无命中 | A |
| 3 | **无 HTTPS** → 会话 Cookie 明文传输，不能上公网 | `config.js:96` `cookieSecure: false` | A |
| 4 | **前端 500KB 且 `Cache-Control: no-store`** → 每次刷新重下整包 | `http-kernel.js:169` 全局设 no-store；静态服务无 ETag | A（体验） |
| 5 | **无备份与恢复**，库文件删了就全丢 | 全仓无备份脚本（只有注释讨论备份重要性） | A（安全网）/ B |
| 6 | **没有真实简历入口**：候选人只能由 `seed-candidates` 合成 | `routes.js:317` 仅有合成种子；无文件上传 / 无 PDF 解析 | B |
| 7 | **模型未接入**，按规则打分 | `/api/health` → `mode:"rule"` | B（真实简历质量） |
| 8 | **指标进程内**：重启清零、无 `/metrics` 端点、无告警 | `metrics.js` 用内存固定桶 | B |
| 9 | **单租户写死** `const TENANT = 'T-001'` | `routes.js:30` | C |
| 10 | **SQLite 单写者**，并发写有天花板 | `db.js` + ADR-005 | C |
| 11 | 数据治理半落地（有 `consent_given` / `retain_until` 字段，无删除/加密闭环） | `db.js` 注释 vs 无实现 | C |
| 12 | CORS 仍允许 `X-User` 头（服务端已不读它） | `http-kernel.js:204` | 噪音，顺手清 |

> **一句话结论**：**它不是一个「功能不全的半成品」，是一个「功能齐全但别人访问不到、数据没兜底、真简历进不来」的作品。** 前两点属于 A 档，第三点属于 B 档。

## 二、A 档 · 让面试官点开就能用（1–2 天，性价比最高）

### A1 · 先选「怎么让别人访问到」——三条路，按场景挑

| 路径 | 适用 | 耗时 | 代价 |
|---|---|:--:|---|
| **① 内网直连** | 面试现场、同事在同一 WiFi | 5 分钟 | 只能同网段访问 |
| **② 临时公网隧道**（推荐给面试） | 给面试官一个链接，他随时能点 | 10 分钟 | URL 每次重启会变、**公开可访问**（需配 A4） |
| **③ 云服务器正式部署** | 长期可用、多人用 | 半天 | 需要服务器与域名 |

**路径 ①（最快）**：改绑所有网卡，用本机局域网 IP 访问。

```bash
# server/.env
HOST=0.0.0.0
PORT=8788
```

然后 `ipconfig` 查本机 IP（如 `192.168.1.20`），同一 WiFi 下的人访问 `http://192.168.1.20:8788`。
⚠️ 此时**不要**设 `COOKIE_SECURE=1`——HTTP 下 Secure Cookie 不会被浏览器发送，你会登录不上（见 A3）。

**路径 ②（面试首选）**：本地照常跑在 `127.0.0.1`，用 Cloudflare 快速隧道把它暴露成一个 HTTPS 公网地址。

```bash
# 安装（Windows）
winget install --id Cloudflare.cloudflared

# 起隧道（保持本地服务在跑）
cloudflared tunnel --url http://127.0.0.1:8788
# → 输出形如 https://xxxx-yyyy.trycloudflare.com 的公网地址，自带证书
```

**它顺带解决了三件事**：HTTPS（第 3 条缺口）、边缘 gzip 压缩（第 4 条的一半）、公网可达（第 1 条）。**代价是必须做 A4**——因为此刻全世界都能访问你的演示系统。

### A2 · 云服务器正式部署（如果要长期可用）

三步：容器化 → 反代 + 自动证书 → 守护进程。

**⚠️ 容器化前必须先改一处代码**：现在数据库路径与会话密钥都写死在 `server/` 目录下（`config.js:47`、`config.js:153`），容器重启即丢。要先让它们可配置并挂卷：

```js
// server/config.js —— 建议改法（当前是写死的）
db: { file: str('DB_FILE', path.join(SERVER_DIR, 'hr_agent.db')) },
// 会话密钥同理：secretFile: str('SESSION_SECRET_FILE', path.join(SERVER_DIR, '.session_secret'))
```

改完再容器化，数据才落在卷上而不是容器里。

```dockerfile
# Dockerfile（放在仓库根）
FROM node:22-alpine
WORKDIR /app
COPY package.json ./
COPY server ./server
COPY shared ./shared
COPY 平台原型 ./平台原型
ENV NODE_ENV=production HOST=0.0.0.0 PORT=8788 \
    DB_FILE=/data/hr_agent.db SESSION_SECRET_FILE=/data/.session_secret
VOLUME ["/data"]
EXPOSE 8788
# node:sqlite 在 Node 22 需显式开启实验开关；Node 24+ 可去掉
CMD ["node","--experimental-sqlite","server/server.js"]
```

```bash
docker build -t hr-agent .
docker run -d --name hr-agent \
  -p 127.0.0.1:8788:8788 \
  -v /srv/hr-agent/data:/data \
  --restart unless-stopped \
  hr-agent
```

**反代 + 自动 HTTPS（Caddy，两行配置）**：

```caddyfile
# /etc/caddy/Caddyfile
hr.example.com {
  reverse_proxy 127.0.0.1:8788
  encode gzip               # 补上缺失的压缩
}
```

Caddy 会自动申请并续期 Let's Encrypt 证书——**不需要你手写任何 TLS 配置**。

**守护（不用 Docker 时）**：

```ini
# /etc/systemd/system/hr-agent.service
[Unit]
Description=HR-Agent OS
After=network.target

[Service]
WorkingDirectory=/opt/hr-agent
ExecStart=/usr/bin/node --experimental-sqlite server/server.js
Environment=NODE_ENV=production HOST=127.0.0.1 PORT=8788 COOKIE_SECURE=1
EnvironmentFile=/opt/hr-agent/server/.env
Restart=always
RestartSec=3
User=hr

[Install]
WantedBy=multi-user.target
```

### A3 · HTTPS 与 `COOKIE_SECURE` 必须成对出现

这是最容易踩的坑：**两个开关要一起动**。

| 场景 | 设置 | 后果 |
|---|---|---|
| 本地 HTTP 演示 | `COOKIE_SECURE` 不设（默认 false） | 正常 |
| 走隧道 / 域名（HTTPS） | `NODE_ENV=production` + `COOKIE_SECURE=1` | 正常，且生产校验会**强制**你设（`config.js:140`） |
| 只设了 `COOKIE_SECURE=1` 却用 HTTP 访问 | —— | ❌ 登录成功但 Cookie 不发送 → **表现为「一直没登录」** |

第三条是最真实的排障陷阱，先记住它。

---

### A4 · 演示安全网（一旦公网可达，**必做**）

`config.js` 层面做了很多正确的事，但它保护不了你自己制造的暴露面。公网可达后，演示口令 `Demo@2026`（`auth.js:27`）和 `/api/admin/reset` 这类接口对任何人开放。四件事：

1. **改掉共享演示口令**：设 `DEMO_PASSWORD` 环境变量为一次性强口令，或干脆给面试官一个**只读演示账号**。
2. **危险接口加开关**：`/api/admin/reset`（清库重灌）在公网演示时必须禁用——建议加 `ALLOW_RESET=1` 之类的显式开关，默认关。
3. **演示数据冻结**：面试前跑一次 `npm run start:reset`，得到一个**确定的初始态**（同样的岗位、同样的候选人、同样的评分）——这样你彩排和现场看到的完全一致。
4. **定时重置兜底**：若面试官会自己乱点，加一个每小时重置的计划任务，保证回到干净态。

> 判断依据很简单：**「演示」的失败不是报错，是被改坏之后再也回不到你准备好的那一版。**

### A5 · 三处顺手清理（各 10 分钟）

| 清理项 | 位置 | 为什么 |
|---|---|---|
| 删掉 CORS 里的 `X-User` | `http-kernel.js:204` | 服务端早已不读它，但允许它会让任何看代码的人怀疑「是不是还留着后门」 |
| 加 `server/.env.example` | 新建 | 部署时**必须**知道有哪些开关（现在只能翻 `config.js` 源码） |
| 静态资源给 ETag / 长缓存，`no-store` 只留给 API | `http-kernel.js:169`、`serveStatic()` | 500KB 前端每次刷新重下；单文件内容变了文件名不变，用 ETag 最稳 |

## 三、B 档 · 给一个真实 HR 小组用（2–4 周）

到这里才需要动这些。顺序不能反。

### B1 · 备份与恢复（**第一优先，先于一切功能**）

有数据的系统，**没有备份就等于数据已经丢了**。SQLite 的在线备份只需一行：

```js
// tools/backup.js（零依赖，可在服务运行时执行）
db.exec(`VACUUM INTO 'backups/hr_${stamp}.db'`);   // 事务一致，不锁写者
```

配一个每日计划任务 + 保留最近 N 份 + **每季度做一次恢复演练**（把备份文件当主库起一次，确认真的能用）。

> 为什么要强调「演练」：`db.js:427` 的注释自己写过这个坑——「备份脚本看文件名对、大小非零，就以为备份成功，恢复时才发现少数据」。

### B2 · 真实简历入口（这是「真用」的门槛）

现状：候选人只能由 `POST /api/jobs/:id/seed-candidates` 合成（`routes.js:317`），**没有任何文件上传或文本粘贴通道**。而真实 HR 手里的简历是 PDF / Word。

零依赖约束下两条路：
- **薄方案**：前端解析 PDF（`pdf.js` 一个文件）+ 把文本 POST 给现有接口 → 改动最小，但解析质量不可控；
- **稳方案**：服务端收文件落对象存储，抽取文本后入库 → 多一个依赖（如 `pdf-parse`），但可控。

⚠️ 无论哪条，**简历文本属于个人信息**，落盘与备份都要纳入 `docs/05` P1-3 说的治理闭环。

### B3 · 模型接入（否则真实简历的评分质量撑不住）

规则模式在**种子数据**上表现可控，但真实简历的措辞千变万化，纯关键词覆盖率打分必然失真。而项目已经为此做好了准备：

- `engine.js` 里 `llm()` 骨架已实现（超时 20s、失败返回 `null` 由上层降级）；
- `config.js:119-124` 三个环境变量已预留；
- `agent_tasks.token_cost` 字段已建。

接入后仍要补的（`docs/05` P2-3 已列）：**供应商抽象（换模型只改配置）、重试退避、token 真实记账、Prompt 版本化**。

> 顺序提醒：**先有评测集，再接模型。** 这个项目已经有 30 例黄金集（`tools/golden/golden_set.json`）——接模型后立刻能回答「涨了还是跌了」。没有评测就接模型，等于把可解释的规则换成不可解释的玄学。

### B4 · 运维补齐

| 项 | 现状 | 要加 |
|---|---|---|
| 指标 | 进程内固定桶，重启清零 | 暴露 `/metrics`（Prometheus 文本格式），换实现不改契约 |
| 告警 | 无 | 错误率 / 健康检查失败 → 至少一条通知（邮件或企微机器人） |
| 日志 | 有结构化日志文件 | 加轮转（否则磁盘会被写满） |
| 进程 | 手动启动 | systemd / Docker `--restart` + 健康检查探测 |

### B5 · 身份：从演示口令换成企业身份源

现在所有账号共享一个初始口令（`auth.js:26-27`，带 `must_change_password=1`）。真实团队要接**企业微信 / 钉钉 / LDAP / OIDC**，且不自己存密码。
好消息是**架构已经对了**：会话表是真相来源、支持即时吊销（`revokeAllForUser`）——换身份源只需替换 `POST /api/auth/login` 的实现，**不用动授权与审计**。

## 四、C 档 · 对外卖（2–6 月）

这一档才是 `docs/05` 写的内容，此处只给顺序（细节见那份文档）：

| 阶段 | 做什么 | 为什么这个顺序 |
|:--:|---|---|
| ① | **PostgreSQL** + 连接池（表结构与 PG 同源，只需换适配层） | 解并发写天花板；这是高风险动作，要在数据还少时做 |
| ② | **多租户 RLS**（把 `const TENANT = 'T-001'` 换成数据库级行级安全） | 「靠约束不靠约定」；现在漏一个 `WHERE` 就是跨客户数据泄漏 |
| ③ | **数据治理闭环**：到期自动清理、PII 加密、数据主体删除接口 | 《个人信息保护法》硬要求；HR 数据是最敏感的一类 |
| ④ | **合规与运营**：等保材料、SLA、计费、审计导出 | 到这一步才敢签合同 |

## 五、别做的事（省下的是几周）

| 别做 | 为什么 |
|---|---|
| ❌ 在 A 档就换 PostgreSQL | 换库是高风险数据迁移；目的是「让别人点开能用」，跟数据库无关 |
| ❌ 上线前做多租户 | 只有一个客户时，多租户是纯粹的成本，不产生任何价值 |
| ❌ 为了「看起来是 AI」先接模型 | 没有评测的模型接入 = 把可解释的规则换成不可解释的玄学，且无法回答效果问题 |
| ❌ 把「企业级」当成上线前提 | 「可用」和「企业级」是两件事；前者 2 天，后者半年 |

## 六、最小可用路径（如果只做一件事）

> **把 `127.0.0.1` 换成别人能点开的地址，并且让数据每天备份一次。**

具体到命令，就是：

```bash
# 1. 起服务（照旧）
npm start

# 2. 另开一个终端，10 秒拿到公网 HTTPS 地址
cloudflared tunnel --url http://127.0.0.1:8788

# 3. 把地址发给面试官；面试前先 npm run start:reset 冻结演示数据
```

**加上 A4 的四条安全网，这已经是一个「可以用的软件」**——只是它的使用者是面试官而不是 HR 团队。而对一个 AI 产品经理的面试来说，**能让面试官亲自点一遍**，比任何架构文档都有说服力。

## 附录 B · 一句话回答「离能用的软件还差什么」

> 「差的不是功能。认证、权限、审计、迁移、测试、压测我都做完了，9 个套件全绿。
> 差的是三件跟功能无关的事：**别人访问不到**（绑在 127.0.0.1、没有部署产物）、**数据没有兜底**（没有备份）、**真实简历进不来**（只有合成数据）。
> 前两件是 1–2 天的事——隧道加 HTTPS、加一份每日备份，它就是一个能让面试官亲自点一遍的东西。第三件加上模型接入，才是能给真实 HR 小组用。
> 至于换 PostgreSQL、做多租户，那是『卖给别人』才需要的；**只有第一个客户还没来的时候就做多租户，才会永远等不到那个客户。**」
