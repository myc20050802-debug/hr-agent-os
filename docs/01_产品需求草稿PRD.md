# B 端 HR AI Agent SaaS 平台 · 产品需求草稿（PRD Draft v0.9）

> **产品代号**：HR-Agent OS（暂定名，可替换）
> **文档用途**：产品立项沟通 + PRD 撰写底稿 + 研发排期输入
> **阅读方式**：非技术同学只看「📌 一句话结论」和表格；技术同学重点看第二、四、五部分
> **一句话概括**：把 HR 每天重复问、重复填、重复催的活儿，交给四个会自己拆任务、会自己调系统的 AI 智能体去干，HR 只做「拍板」和「兜底」。

---

## 0. 先统一语言（术语表，通俗版）

| 术语 | 说人话 |
|---|---|
| **Agent（智能体）** | 一个能听懂目标、自己拆步骤、自己动手干活的 AI 员工。比如你说「把这批简历筛一遍」，它会自己决定先读 JD、再读简历、再打分、最后给你一张排序表 |
| **LLM（大模型）** | Agent 的「大脑」，负责理解语言和做判断，但它不能自己去查系统数据 |
| **Tool / 工具调用** | Agent 的「手」。它要查考勤、发邮件、建入职单，都得通过工具去调系统的接口 |
| **RAG（检索增强）** | Agent 的「翻手册」能力：先在你的公司制度文档里找到依据，再回答员工，避免瞎编 |
| **Workflow（工作流）** | 固定的流水线，步骤写死、顺序固定，比如「入职 7 天前发提醒」——这种不需要 AI，用规则跑更省钱更可靠 |
| **HITL（人工介入）** | 高风险动作必须停下来等人点「同意」。比如给候选人发 Offer，AI 只能起草，人必须签字 |
| **SaaS 多租户** | 一套系统同时服务很多家公司，数据互相绝对隔离，A 公司永远看不到 B 公司的数据 |

> **关键工作原则（贯穿全文）**：**Agent 负责判断，Workflow 负责执行，规则/代码负责约束，人负责治理。**
> 凡是一句 `if-else` 能搞定的事，绝不用大模型。这是这套产品能不能赚钱的生死线。

## 第一部分 · 产品定位、目标客户与核心价值

### 1.1 📌 一句话定位

> **面向 200～5000 人规模企业的「HR 数字员工平台」**：把招聘、入转调离、员工咨询、人力报表四件事，从「HR 手工操作」升级为「AI 自主执行 + 人审核确认」，HR 从执行者变成管理者。

### 1.2 现在的痛，到底痛在哪（As-Is 现状）

不要直接抄需求，先看真实场景。以下是我们调研得到的典型一天（As-Is）：

| 序号 | HR 的真实一天 | 耗时 | 病根（Root Cause） |
|---|---|---|---|
| 1 | 翻 80 份简历，逐个看学历/年限/技能，凭感觉分堆 | 3～4 小时 | 判断标准在脑子里，没有结构化，无法复用 |
| 2 | 挨个给候选人打电话/发微信约面试，来回改时间 | 1.5 小时 | 协调类工作无法批量处理 |
| 3 | 员工微信问「年假还剩几天」「社保基数怎么算」，一天被打断 20 次 | 2 小时 | 制度文档写得很全，但员工懒得翻、HR 懒得答 |
| 4 | 每月手工扒考勤、做招聘漏斗、拼周报 | 4 小时/月 | 数据散在 ATS、考勤机、Excel 里，靠人工搬运 |
| 5 | 入职材料催 8 遍还收不齐，转正日期记错导致纠纷 | 隐性风险 | 流程靠人记，没有系统盯着 |

**共性病根一句话**：**HR 的工作 80% 是「查资料 + 搬数据 + 催流程」，只有 20% 才是「做判断」。**
而这 80% 恰好是大模型和 Agent 最擅长、也最容易被量化的部分。

### 1.3 目标客户分层

| 分层 | 规模 | 典型特征 | 我们卖什么 | 客单预期 |
|---|---|---|---|---|
| **主力客群（一期）** | 200～1000 人 | 有 HR 团队 3～10 人，用飞书/钉钉，ATS 可能只是 Excel | 招聘 Agent + 员工自助 Agent | 中等 |
| **扩展客群（二期）** | 1000～5000 人 | 有独立 HRIS/OA，流程复杂、合规要求高 | 全模块 + Agent 编排 + 私有化部署 | 高 |
| **长尾（三期，标准化）** | 50～200 人 | 只有 1～2 个 HR，最痛但最没钱 | 单点 SaaS（只买员工自助 + 简历筛选） | 低，走量 |

**一期不建议碰**：50 人以下（付费能力弱、决策周期却一样长）、以及超大型集团（定制化黑洞，会拖垮交付）。

### 1.4 核心价值：卖的不是 AI，是三个数字

| 价值主张 | 客户语言（销售话术） | 对应可量化指标 |
|---|---|---|
| **省时间** | 「你们 HR 每天花 3 小时筛简历，我们能压到 20 分钟复核」 | 简历初筛人效提升 ≥ 70% |
| **少出错** | 「转正漏提醒、材料收不齐这种事，系统会替你盯着，出事有留痕」 | 流程逾期率下降 ≥ 60% |
| **能说清** | 「老板问上个月招聘情况，30 秒出一张漏斗图，不用现算」 | 报表产出时间从 4 小时 → 5 分钟 |

### 1.5 核心价值链路（KPI 树）

```
业务目标：让 HR 团队用同样人数，支撑更多员工 / 更快招聘
  └─ 北极星指标（North Star）：每周由 AI 完成并被采纳的 HR 任务数（Accepted AI Tasks / Week）
       ├─ 业务 KPI：招聘周期（Time to Hire）、单人 HR 支持员工数、流程逾期率
       ├─ 产品指标：Agent 任务完成率、采纳率、人工接管率、周活跃 HR 数
       ├─ AI 指标：简历打分与人工判断一致率、问答有依据率（引用命中率）、幻觉率
       └─ 护栏指标（Guardrail）：越权访问次数（必须为 0）、敏感信息外泄次数（0）、高风险动作未经审批执行数（0）
```

> **为什么要护栏指标？** 因为 B 端 HR 系统一旦泄露简历或错发 Offer，客户会直接解约。护栏指标不为 0，前面所有增长都是泡沫。

### 1.6 明确不做什么（Non-goals）

| 不做 | 原因 |
|---|---|
| 不做完整 HRIS/薪酬核算系统 | 这是北森/Workday 的地盘，我们做 AI 层，通过接口读写他们 |
| 不做自动发 Offer / 自动辞退 | 高风险不可逆，法律与舆情成本远高于省下的工时 |
| 不做「全自动无人招聘」 | 招聘本质是人的判断，AI 做的是「排好序 + 备好材料」 |
| 不做简历爬虫抓取 | 数据来源必须合法授权，否则是给客户埋雷 |
| 一期不做多模态视频面试分析 | 反歧视合规风险高，且技术不成熟，容易被投诉 |

### 2.2 各层职责表（谁干什么，别越界）

| 层 | 核心职责 | 关键技术点 | 常见坑 |
|---|---|---|---|
| ① 前端展现 | 让人看得懂、点得动、能撤销 | 支持表单 + 对话 + 看板三种形态混用，**不要做成纯聊天窗口** | 所有事都塞进聊天框，用户找不到历史记录 |
| ② Agent 调度 | 拆任务、发工具、卡权限、逼人工审核 | 编排引擎 + 工具注册中心 + HITL 闸门 | 把业务逻辑写进 Prompt，导致不可测试、不可审计 |
| ③ 大模型 | 提供理解与生成能力 | 多模型路由：便宜模型干粗活，强模型干细活 | 所有任务都调最贵模型，成本失控 |
| ④ 能力/数据 | 提供事实依据 | 向量库 + 业务库；**事实以业务库为准，知识库只做解释** | 让向量库里的过期制度文档覆盖真实考勤数据 |
| ⑤ 第三方对接 | 真正去执行动作 | 统一适配器 + 幂等键 + 失败重试 | 没有幂等，重试一次就发出两封面试邀请 |
| ⑥ 基础设施 | 隔离、审计、可恢复 | 行级租户隔离 + 字段级脱敏 | 多租户共用表却忘了加 tenant_id 过滤 |

### 2.3 第三方对接层清单（这块决定交付能不能落地）

| 对接对象 | 用来干什么 | 对接方式 | 关键字段 | 失败怎么办（降级策略） |
|---|---|---|---|---|
| **ATS**（Moka / 北森 / 大易 / 自研 / Excel） | 拉取候选人、回写筛选结果与阶段 | OpenAPI 优先，无 API 则用 CSV 导入导出 + 邮件解析 | 候选人 ID、岗位、阶段、简历附件、来源渠道 | API 挂了→切「导入导出模式」，Agent 结果落成本地待同步队列 |
| **飞书** | 审批、日历、群机器人、消息卡片 | 开放平台 API + 机器人 Webhook | user_id、审批实例、日历事件 | 降级到「站内待办 + 邮件」 |
| **钉钉** | 同飞书 | 开放平台 API | userid、待办任务、工作通知 | 同上 |
| **企业微信** | 员工咨询入口（员工最常用） | 应用消息 + 会话存档（合规需授权） | 员工企微 ID、会话 ID | 降级到 H5 员工端 |
| **OA / 审批** | 发起入职、转正、离职审批流 | 标准 API / 中间表 | 流程模板 ID、审批状态 | 降级为「平台内审批 + 回调同步」 |
| **邮件** | 面试邀约、Offer、材料催收 | SMTP 发信 / IMAP 收信 | 收发件人、模板 ID、附件 | 失败自动重试 3 次 → 转人工提醒 |
| **日历** | 面试官与候选人时间协调 | CalDAV / 飞书日历 API | 忙闲时段、会议室 | 只给时间建议，不自动创建会议（一期保守） |
| **知识库** | 员工问答依据 | 飞书云文档 / 语雀 / Confluence / 本地 PDF/Word 上传 | 文档 ID、版本、生效日期、可见范围 | 无命中→明确回答「未找到依据，已转 HR」 |
| **电子签** | Offer、劳动合同签署 | e签宝 / 法大大 | 签署任务 ID、状态 | 降级为线下签署 + 上传回执 |
| **考勤机 / 考勤系统** | 年假、考勤答疑 | API / 报表导出 | 员工 ID、假期余额、打卡记录 | 只读不写（一期不允许 AI 改考勤） |

> **统一要求**：所有对接必须走同一个「工具适配器」规范——统一鉴权、统一重试、统一幂等键、统一日志。**每接一家系统，只写一个适配器，不允许业务代码直连。**

### 2.4 一条数据流把架构串起来（招聘 Agent 示例）

```
HR 说：帮我筛一下「高级 Java 工程师」这个岗位的新简历
  │
  ├─[② 调度层] 意图识别 → 生成任务计划（Task Plan）：
  │      步骤1 读取岗位 JD           → 工具：ATS.getJob(jobId)
  │      步骤2 拉取近 3 日新简历      → 工具：ATS.listResumes(jobId, since)
  │      步骤3 解析简历为结构化字段   → 工具：Resume.parse（OCR+信息抽取）
  │      步骤4 按 JD 要求逐项打分     → 工具：LLM.rank（结构化输出 JSON）
  │      步骤5 敏感信息脱敏          → 工具：PII.mask（姓名/电话/性别/年龄）
  │      步骤6 写回 ATS 并生成推荐表   → 工具：ATS.updateStage（需人工确认）
  │
  ├─[③ 模型层] 步骤4 调推理模型；步骤3 调 OCR + 抽取模型；步骤5 走规则，不调模型
  ├─[④ 数据层] 步骤1/2 读业务库（权威事实）；步骤4 引用岗位胜任力标准（知识库）
  ├─[⑤ 对接层] 步骤1/2/6 调 ATS；输出结果同时推送飞书卡片给 HR
  └─[⑥ 治理层] 全程落 Trace：谁发起、调了哪些工具、每步耗时、token 花费、是否触发审核
```

### 2.5 技术选型建议与理由

| 组件 | 建议选型 | 为什么 |
|---|---|---|
| Agent 编排 | 自研轻量编排引擎（状态机 + 任务队列），或 LangGraph / Dify 二次封装 | 直接上 Multi-Agent 框架容易失控；先用「单 Agent + 固定工具集」跑通 |
| 向量库 | pgvector / Milvus / 云托管向量服务 | 2000 人以下企业文档量不大，pgvector 够用且少一套运维 |
| 主数据库 | PostgreSQL（多租户 + 行级安全 RLS） | 自带 RLS，天然适合 SaaS 数据隔离 |
| 缓存/队列 | Redis + 消息队列 | 任务重试、限流、异步工具调用 |
| 文件存储 | S3 兼容对象存储 + 服务端加密 | 简历属于敏感个人信息，必须加密 + 有效期删除 |
| 模型接入 | 统一 LLM 网关（多厂商可切换） | 客户会问「能不能用国产模型 / 私有化」，网关层解耦 |
| 前端 | React / Vue 单页应用 | 后台表单多、状态多，SPA 体验更好 |
| 可观测 | OpenTelemetry + 自建 Trace 看板 | Agent 出问题必须能回放每一步 |

### 2.6 架构自我挑战（必须承认的风险）

| 风险 | 表现 | 应对 |
|---|---|---|
| **过度 Agent 化** | 把「每月 1 号发转正提醒」也做成 Agent，成本和稳定性双输 | 强规则场景一律用 Workflow + 定时任务 |
| **上下文膨胀** | 把整个知识库塞进 Prompt，token 费爆炸且答得更差 | 先检索后注入，只给 Top-K 片段 |
| **不可评测** | 没有标准答案，无法判断改了 Prompt 是变好还是变坏 | 上线前必须建回归测试集（见第六部分） |
| **单点故障** | 模型服务或 ATS 挂了整个产品不可用 | 双模型路由 + 降级到人工队列 |
| **权限穿透** | Agent 用了「系统账号」越权读全公司数据 | Agent 必须以「发起人身份」执行，权限继承发起人 |

## 第三部分 · 分模块详细功能

### 3.1 招聘 Agent

**岗位定位**：HR 的「招聘助理」，负责把「找简历→约面试→准备面试→发 Offer 前置材料」这条链路做工业化。

#### 3.1.1 功能总览

| 子功能 | AI 做什么 | 人做什么 | 自动化等级 |
|---|---|---|---|
| ① JD 生成与优化 | 根据岗位需求草稿生成完整 JD、优化措辞、检查歧视性用语 | 修改并发布 | L2（AI 生成、人确认） |
| ② 简历解析 | 把 PDF/图片简历变成结构化字段 | 处理解析失败件 | L4（自动执行、异常人工） |
| ③ 简历筛选打分 | 按 JD 硬性条件 + 能力项打分并排序 | 复核 Top 名单 | L2（AI 生成、人确认） |
| ④ 候选人邀约与调度 | 生成邀约话术、给时间建议、发信、催确认 | 异常/拒绝时介入 | L3（执行前确认，可开自动） |
| ⑤ 面试辅助 | 生成面试提纲、追问建议、面试纪要 | 面试官主导 | L1（AI 建议） |
| ⑥ Offer 及入职前置 | 生成 Offer 草稿、薪资对比提示、入职材料清单 | 审批与签署 | L1～L2（严禁 L4） |

#### 3.1.2 各子功能详细规则

**① JD 生成优化**
- **输入**：岗位名称、部门、汇报对象、薪资范围、必须项/加分项（可用自然语言写，如「3 年以上 Java，懂高并发，能接受出差」，**只写一条也可以**）
- **输出**：结构化 JD（岗位职责 5～8 条、任职要求、加分项、我们提供什么）
- **任职要求六维度**（核心要求，不允许只输出一条干巴巴的要求）：

  | 维度 | 内容来源 |
  |---|---|
  | 专业技能 | HR 已填内容原样保留 + 行业技能词库中未被提到的核心技能补位 |
  | 工作经验 | HR 已填年限要求 + 该行业的经历特征（如制造业看现场经验、销售看完整销售周期） |
  | 学历背景 | 按岗位设定的学历门槛生成 + 行业对口专业方向 |
  | 综合素质 | 行业化职业素养（如医疗看重查对制度、金融看重合规红线） |
  | 软技能 | 跨部门协作、抗压、学习力等行业化表述 |
  | 加分项 | HR 已填优先；已填 ≥3 条则不再叠加模板，避免同义重复 |

- **关键约束**：**HR 自己写的那条要求必须原样保留并归位到对应维度**，AI 只做补齐与专业化，不改写原句（避免 HR 认不出自己的岗位）
- **内置规则（必须做）**：
  - 歧视性用词扫描：性别、婚育、年龄（「35 岁以下」）、地域、院校层级、外貌 → 命中即黄色警告并给替换建议
  - 法律话术检查：避免「试用期不合格不付工资」等违法表述
- **验收**：歧视词拦截率 100%（回归集至少 30 条样本）；单条输入 → 输出 ≥5 维度、≥12 条任职要求

**② 简历解析**
- 抽取字段：姓名、联系方式、教育经历（学校/专业/学历/时间）、工作经历（公司/岗位/起止/职责）、技能标签、项目经历
- 支持格式：PDF（含扫描件 OCR）、Word、图片、ATS 结构化字段
- **质量要求**：关键字段（学历、工作年限、最近一家公司）抽取准确率 ≥ 95%；解析失败必须显式标红「需人工补录」，**不允许猜**
- **脱敏**：解析完成后，送入排序环节前先做 PII 脱敏（见第四部分）

**③ 简历筛选打分**（本模块最核心，也最容易翻车）
- **打分维度必须显式配置，不能是黑盒**：

| 维度 | 权重（可配） | 判定方式 |
|---|---|---|
| 硬性门槛（学历/证书/工作年限） | 一票否决项 | 规则判定，不调模型 |
| 技能匹配度 | 40% | 模型判断 + 技能词典 |
| 行业/业务匹配度 | 30% | 模型判断 |
| 稳定性（跳槽频率） | 15% | 规则计算 |
| 加分项（开源、专利、大厂背景） | 15% | 模型 + 规则 |

- **输出**：分数（0～100）+ **推荐等级（强烈推荐/可聊/不合适）** + **逐条理由**（引用简历原句）
- **强制约束**：
  - 性别、年龄、婚育、户籍、照片**不得进入打分输入**（技术手段：进入模型前物理删除字段）
  - 每条分数必须能追溯到简历原文，禁止「凭空印象分」
  - HR 推翻 AI 判断时，必须记录「推翻原因」，用于后续优化（这是最重要的训练数据）
- **验收**：与资深 HR 人工排序的 Top 10 重合率 ≥ 70%；歧视字段零泄漏

**④ 候选人邀约与调度**
- 生成个性化邀约（邮件/短信/微信），含岗位、面试形式、时长、可选时段、联系人
- **时间协调逻辑**：读取面试官日历忙闲 → 给 3 个候选时段 → 候选人确认 → 创建日历邀请（一期必须先给 HR 确认再发）
- **催办**：候选人 24h 未回复 → 自动跟进 1 次；48h 未回复 → 转人工
- **合规硬要求**：所有邀约信必须含退订/拒绝说明，且记录发送时间与内容（留痕）

**⑤ 面试辅助**
- 面试前：生成结构化面试提纲（考察维度 → 对应问题 → 期望回答要点 → 追问路径）
- 面试中（可选）：实时转写 + 关键信息标记
- 面试后：生成纪要草稿 + 评价表建议（**不给录用建议**，只做整理）

**⑥ Offer 及入职前置**
- 生成 Offer 草稿（**只起草，不发送**，必须走审批）
- 薪资合规检查：是否低于岗位薪资带宽下限、是否超出预算审批线
- 自动生成入职材料清单，并移交「入转调离 Agent」

### 3.2 入转调离 Agent

**岗位定位**：HR 的「流程管家」，负责盯时间、催材料、留痕迹。

#### 3.2.1 四条流程

| 流程 | 触发 | AI 自动做的事 | 强制人工确认的事 |
|---|---|---|---|
| **入职** | Offer 接受 / 手动创建 | 生成材料清单、按天催收、OCR 校验材料完整性、发起账号开通审批 | 合同签署、权限开通 |
| **转正** | 试用期到期前 N 天（默认 15/7/3/1） | 提前提醒直属上级、拉取试用期考核表、汇总待办 | 转正结论、薪资调整 |
| **调岗** | 调岗审批通过 | 生成调岗材料清单、同步更新组织架构树、通知相关系统 | 职级/薪资变更 |
| **离职** | 离职申请通过 | 生成交接清单、资产归还提醒、账号回收审批单、离职证明草稿 | 账号注销、证明盖章 |

#### 3.2.2 关键设计

- **时间轴引擎（Workflow，不用 AI）**：所有「提前几天提醒」都是确定性任务，用定时任务 + 规则，稳定且零成本
- **AI 只用在三个地方**：① 生成的提醒文案因人而异（新人 vs 高管话术不同）② 材料 OCR 后判断「这张是不是体检报告」③ 员工用自然语言问「我该交什么材料」时给个性化清单
- **材料收集看板**：每位待入职/待转正员工一张卡片，显示「已收 3/6 项」，缺项红色标注，一键催办
- **超期升级**：逾期 2 天 → 提醒 HR；逾期 5 天 → 提醒 HR 上级
- **验收**：流程按期完成率 ≥ 90%；材料漏项率 ≤ 2%

### 3.3 员工自助 Agent

**岗位定位**：7×24 小时回答员工问题，把 HR 从「人肉客服」里解放出来。

#### 3.3.1 功能

| 能力 | 说明 |
|---|---|
| 自然语言问答 | 「我还有几天年假？」「社保基数怎么算？」「报销流程是什么？」 |
| 多入口 | 企业微信 / 飞书 / 钉钉机器人 + H5 员工端 |
| 有依据回答 | 每个答案附「依据来源」（制度文件章节 + 最后更新时间），可点击查看原文 |
| 个人数据查询 | 年假余额、考勤异常、薪资条位置、社保缴纳记录（**只看自己的**，权限强制校验） |
| 无答案兜底 | 检索不到就明说「没找到依据」，一键转 HR，并记录这个未被回答的问题（这是知识库补全清单） |
| 主动推送 | 试用期到期、年假将清零、体检预约、政策变更提醒 |

#### 3.3.2 关键规则（这块最容易出事）

1. **事实分层**：涉及个人数字（年假/薪资/考勤）**必须查业务系统**，不许用知识库里的文档回答；制度解释类才用知识库
2. **冲突处理**：知识库文档与业务系统数据冲突时，以业务系统为准，并提示「制度文件可能已过期，已通知管理员」
3. **权限硬隔离**：员工 A 问不到员工 B 的任何数据，即使用自然语言绕过（「帮我算算张三的年假」）也必须拒绝
4. **禁止**：不给法律意见、不做薪资谈判建议、不评价同事/领导、不解读劳动合同纠纷 → 一律转 HR 或法务
5. **测不准就说不知道**：设置「置信度阈值」，低于阈值不硬答

- **验收**：常见问题（Top 50）自助解决率 ≥ 60%；答非所问率 ≤ 5%；零越权访问

### 3.4 人力报表 Agent

**岗位定位**：把数据搬进搬出的活儿全干掉，让 HR 一句话出图。

#### 3.4.1 报表清单

| 报表 | 内容 | 更新频率 | 交付形态 |
|---|---|---|---|
| **招聘漏斗** | 各岗位：投递 → 初筛 → 面试 → Offer → 入职，含转化率、平均耗时、渠道效果 | 每日自动 | 看板 + 飞书卡片推送 |
| **人力日报/周报** | 入职/离职/异动、在招岗位、面试安排、待办预警 | 每日 9:00 / 每周一 9:00 | 图文推送 |
| **月度人力月报** | 编制与实配、人员流动率、招聘完成率、人力成本概览 | 每月 1 日 | 报告文档 + 看板 |
| **自定义问数** | 「上季度技术部离职率」→ 自动生成图表和结论 | 随问随查 | 图表 + 一句话结论 |
| **异常预警** | 离职率突增、某岗位长期招不满、简历积压 | 实时 | 预警卡片 |

#### 3.4.2 关键规则

- **数据必须来自权威库**，不能用模型「估算」；模型只负责：自然语言转查询、挑图表类型、写结论文字
- **口径写死在指标库**：比如「离职率 = 期间离职人数 / 期间平均在编人数」，口径不允许 AI 自由发挥
- **数字必须可下钻**：点某个数字能展开到名单（受权限控制）
- **时间口径**：所有报表默认展示北京时间，日期按**倒序**（最新在最上）
- **验收**：指标与人工核算误差 = 0（因为走的是同一套 SQL）；月报生成时间 ≤ 30 秒

### 3.5 Agent 编排（HR 可低代码配置）

**岗位定位**：让懂业务不懂代码的 HR，自己拼出「简单自动化 Agent 任务」。

#### 3.5.1 编排界面 = 三块积木

```
[触发条件]  →  [执行动作]  →  [审核与通知]
   │              │                │
   │              │                └─ 高风险动作？→ 必须人工审核
   │              │                   结果通知谁？（HR/上级/群）
   │              └─ 调工具：发邮件 / 改 ATS 状态 / 建审批单 / 问大模型 / 查数据库
   └─ 定时（每天 9 点）/ 事件（有新简历）/ 手动 / 条件（试用期剩 7 天）
```

#### 3.5.2 必须支持的能力

| 能力 | 说明 |
|---|---|
| 可视化拖拽 | 不写代码，连线即可 |
| 模板市场 | 内置 10+ 模板：入职欢迎流程、试用期提醒、简历自动初筛、生日祝福、离职交接 |
| 试运行（Dry Run） | 上线前先跑一遍，只展示「会做什么」，不真的执行 |
| 版本与回滚 | 每次修改留版本，可一键回滚 |
| 权限继承 | 编排出的 Agent 继承创建者权限；创建者离职则流程自动暂停待移交 |
| 运行看板 | 每个流程：跑了多少次、成功多少、失败多少、省了多少时间 |

- **验收**：HR 不看文档，30 分钟内能独立配出「试用期到期前 7 天提醒上级」这类流程

## 第四部分 · Agent 底座必须具备的能力

> 这一部分是**平台的地基**。上层四个 Agent 是「租户」，底座是「楼板」。地基不牢，上面全塌。

### 4.1 任务规划拆解（Planner）

**要解决什么**：用户说一句模糊的话，Agent 得知道分几步干、每步用什么工具、什么时候该停下来问人。

| 能力 | 具体要求 |
|---|---|
| 意图理解 | 把「帮我看看这岗位招得怎么样」拆成：拉岗位数据 → 算漏斗 → 生成结论 |
| 计划生成 | 输出版本化的任务计划（Task Plan），**必须落库可回放** |
| 步骤依赖 | 支持串行、并行（如同时解析 50 份简历）、条件分支（材料缺→催收，不缺→发起审批） |
| 动态调整 | 步骤失败时可换工具重试（ATS API 挂了→走导入模式），而不是整单失败 |
| 预算控制 | 每个任务设 token / 时间 / 调用次数上限，超限暂停并通知人 |
| 计划可见 | HR 能看到「它打算怎么干」，并可以改（这是信任的关键） |

**反面案例（必须避免）**：计划不落库，出问题无法复现，只能靠猜。

### 4.2 工具调用（Tool Calling）

| 能力 | 具体要求 |
|---|---|
| 工具注册中心 | 所有工具统一注册：名称、说明、参数 Schema、权限要求、是否高风险、超时时间、幂等键规则 |
| 结构化调用 | 模型只能按 Schema 调，参数不合法直接拒绝，不让模型自由发挥 |
| 幂等保障 | 每个写操作带幂等键（如 `interview_invite:候选ID:轮次`），重试不会重复发信 |
| 失败处理 | 超时/错误 → 指数退避重试 3 次 → 仍失败转人工队列并告警 |
| 高风险标记 | 工具打标：`发送Offer`、`删除数据`、`改薪资` 属于高风险，调用前强制进审核闸门 |
| 审计 | 每次调用记录：谁发起、什么任务、入参、出参、耗时、是否被审核 |
| 权限校验 | 工具执行前校验「发起人是否有权做这件事」，而不是「系统账号有没有权限」 |

### 4.3 长期记忆（Memory）

**关键认知：记忆不是把所有聊天记录存下来，而是分层存储。**

| 记忆层 | 存什么 | 存多久 | 作用 |
|---|---|---|---|
| 会话记忆 | 当前对话上下文 | 会话结束 | 让对话连贯 |
| 用户偏好记忆 | 「这位 HR 喜欢先看分数再看理由」「习惯先筛学历」 | 长期 | 越用越顺手 |
| 任务状态记忆 | 任务跑到第几步、中间结果 | 任务生命周期 | 断点续跑，不重复劳动 |
| 业务事实记忆 | 岗位画像、团队惯例、面试官偏好 | 长期，需人工可编辑 | 提升判断准确度 |
| 企业知识记忆 | 制度文档（向量化） | 跟随文档版本 | 问答依据 |

**硬规则**：
1. **记忆不能覆盖权威事实**。记忆说「张三还在职」，但 HR 系统显示已离职 → 以 HR 系统为准
2. **敏感信息不入长期记忆**。手机号、身份证、薪资不写入记忆层
3. **记忆必须可查看、可删除**（合规要求，员工有权要求删除其个人数据）
4. 记忆写入前需过「脱敏网关」

### 4.4 权限隔离（Permission Isolation）

四层隔离，缺一不可：

| 层级 | 隔离内容 | 实现要点 |
|---|---|---|
| **租户隔离** | A 公司 vs B 公司 | 所有表带 `tenant_id` + 数据库行级安全（RLS），应用层强制过滤 |
| **角色隔离** | HR 专员 / HRBP / HRD / 面试官 / 员工 | RBAC：角色 → 资源 → 动作 → 数据范围 |
| **数据范围隔离** | HR 只能看自己负责的部门/岗位 | 数据权限表达式，如 `dept in (我的负责范围)` |
| **Agent 代理隔离** | Agent 不能超出发起人权限 | **Agent 以发起人身份执行**（二次鉴权），禁止使用超级账号 |

**必须能通过的安全测试**：
- 用员工账号调「查别人薪资」接口 → 必须 403
- 用 HR 专员账号导全公司花名册 → 必须被数据范围拦截
- 让 Agent「帮我把所有候选人电话导出来」→ 必须拒绝并记录

### 4.5 敏感数据脱敏（PII Masking）

**定义敏感级别**：

| 级别 | 字段示例 | 处理方式 |
|---|---|---|
| S4 极敏感 | 身份证号、银行卡、薪资、体检报告 | 默认全部打码，明文需单独授权 + 二次验证，查看留痕 |
| S3 敏感 | 手机号、邮箱、住址、家庭信息 | 列表默认打码（138****8888），点击查看需权限 |
| S2 内部 | 姓名、部门、岗位、绩效等级 | 按角色可见 |
| S1 公开 | 岗位信息、公司制度 | 全员可见 |

**脱敏网关的三道关**：
1. **入模型前**：把 S3/S4 字段从 Prompt 里物理替换为占位符（`[手机号]`），模型永远看不到原文
2. **模型输出后**：扫描输出内容，出现疑似证件号/手机号 → 拦截
3. **用于训练/优化前**：二次脱敏 + 明确授权

**招聘反歧视的技术保障**：简历进入打分模型前，**物理删除**性别、年龄、出生日期、婚育、户籍、照片字段。这不是靠提示词「请不要考虑性别」，而是靠代码删字段——**因为提示词会失效，代码不会**。

### 4.6 高风险操作强制人工审核（HITL 闸门）

**什么是高风险**（清单必须写死）：

| 类别 | 具体动作 | 审核要求 |
|---|---|---|
| 法律效力类 | 发 Offer、签合同、发解除通知、出离职证明 | 必须人工批准，且记录审批人 |
| 金钱类 | 任何薪资/奖金/报销金额的写入 | 必须人工批准 |
| 不可逆类 | 删除候选人、删除员工数据、关闭账号 | 必须人工批准 + 二次确认 |
| 对外沟通类 | 群发邮件/短信（>10 人） | 必须人工预览确认真实内容 |
| 隐私类 | 导出名单、查看身份证原件 | 必须授权 + 留痕 + 限量 |
| 低风险（免审） | 生成草稿、检索、算数、写内部分析 | 自动执行，事后可查 |

**审核闸门设计**：
- **审核队列**：所有待审任务进统一队列，支持批量批准 / 逐条批准
- **卡片式审核**：展示「Agent 想做什么 + 具体内容 + 依据 + 影响范围」，一键通过/驳回/改后发
- **超时策略**：超过 N 小时未审核 → 提醒；超过 2N 小时 → 升级到上级
- **驳回即学习**：驳回必须填原因，原因进入优化数据集
- **禁止绕过**：任何代码路径都不得跳闸门（需要静态检查 + 单测覆盖）

### 4.7 底座能力验收总表

| 能力 | 验收指标 | 通过门槛 |
|---|---|---|
| 任务规划 | 计划落库率、可回放率 | 100% |
| 工具调用 | 幂等测试通过率、超时重试成功率 | 100% / ≥ 95% |
| 长期记忆 | 记忆冲突时以系统数据为准的比例 | 100% |
| 权限隔离 | 越权测试用例通过数 | 100%（0 漏洞） |
| 脱敏 | PII 出现在模型入参中的次数 | 0 |
| 人工审核 | 高风险动作未经审核执行数 | 0 |

## 第五部分 · 合规与安全要求

> 对 B 端 HR 产品，**合规不是加分项，是一票否决项**。

### 5.1 简历隐私（个人信息保护）

| 要求 | 具体做法 |
|---|---|
| 合法来源 | 只处理客户通过合法渠道提供的简历；不爬取、不购买来源不明简历库 |
| 告知同意 | 候选人投递时需勾选隐私条款；平台提供标准条款模板 |
| 最小必要 | 只收集招聘必需字段；身份证、家庭信息不收集 |
| 存储期限 | 简历默认保留 12 个月（可配），到期自动匿名化或删除；进入人才库需候选人单独同意 |
| 加密 | 传输 TLS 1.3；存储 AES-256；简历原件单独加密并限制下载 |
| 地域 | 支持数据不出境（境内客户数据存境内）；支持私有化部署 |
| 删除权 | 候选人可申请删除，系统须在 15 个工作日内完成并留痕 |
| 委托处理 | 与客户签数据处理协议（DPA），明确平台为「受托方」，客户为「处理者」 |

### 5.2 招聘反歧视

| 要求 | 具体做法 |
|---|---|
| 字段禁入 | 性别、年龄、婚育、户籍、户籍地、民族、宗教、照片、健康状况在打分链路中物理移除 |
| JD 扫描 | 上线前扫描 + 每次编辑时实时提示歧视性用语（含隐性表述：「能加班」「形象好」） |
| 打分可解释 | 每条评分给出依据（引用简历原句），禁止黑盒 |
| 差异审计 | 每月自动生成「筛选结果差异报告」：不同性别/年龄段的通过率差异，超阈值告警 |
| 人工复核 | 所有负面结论（不合适）必须可被 HR 推翻并记录 |
| 不采集 | 不主动推断受保护特征（如通过姓名推断性别、通过学校推断地域） |

### 5.3 操作留痕（审计）

**所有关键操作必须可回放**，日志字段规范：

| 字段 | 说明 |
|---|---|
| 时间（北京时间） | 精确到秒 |
| 操作主体 | 人（user_id）/ Agent（agent_id）/ 系统（system） |
| 任务 ID | 关联到具体任务，可回放整个计划的每一步 |
| 动作 | 查询 / 生成 / 修改 / 删除 / 导出 / 发送 / 审批 |
| 对象 | 操作了哪条数据（对象类型 + ID） |
| 前后值 | 修改类操作必须记录变更前/后 |
| 依据 | AI 决策理由、引用的知识片段 |
| 审批链 | 谁审的、什么时候、批注 |
| 结果 | 成功/失败/被拦截 + 原因 |

**保留期限**：操作日志 ≥ 3 年；敏感数据访问日志 ≥ 3 年；不可篡改（WORM 或哈希链）。

### 5.4 多角色权限矩阵

| 角色 | 招聘 | 员工档案 | 薪资 | 报表 | 编排 | 系统设置 |
|---|---|---|---|---|---|---|
| 超管（平台方） | 无业务数据 | 无 | 无 | 无 | 无 | 租户/计费 |
| 企业管理员 | 全部 | 全部 | 可配置 | 全部 | 全部 | 全部 |
| HRD | 全部 | 全部 | 查看 | 全部 | 创建 | 有限 |
| HRBP | 所辖部门 | 所辖部门 | 不可见 | 所辖部门 | 创建 | 无 |
| 招聘专员 | 在招岗位 | 候选人 | 不可见 | 招聘相关 | 创建 | 无 |
| 面试官 | 自己的面试 | 自己面试的候选人 | 不可见 | 无 | 无 | 无 |
| 员工 | 无 | 仅自己 | 仅自己 | 无 | 无 | 无 |
| 审计员 | 只读日志 | 只读 | 只读 | 只读 | 无 | 无 |
| Agent（招聘） | 继承发起人权限 | 继承 | 永不 | 继承 | 无 | 无 |

> **关键**：Agent 的权限栏必须有「永不」项——薪资字段对 Agent 永久只读或不可见。

## 第六部分 · MVP 最小可行产品版本建议

### 6.1 一期做什么（建议 12～16 周）

**选择原则**：选「高频 + 低风险 + 数据易得 + 效果可量化」的场景。

| 模块 | 一期范围 | 为什么先做 |
|---|---|---|
| **员工自助 Agent** | 制度问答（Top 50 问题）+ 年假/考勤查询 + 转人工兜底 | 风险最低、复用最高、员工立刻有感、能积累知识库 |
| **招聘 Agent - 简历解析与打分** | 支持 PDF/Word、结构化解析、按 JD 打分排序、脱敏、人工复核 | 价值最直观（省时间可量化）、有明确验收指标 |
| **招聘 Agent - JD 生成与歧视扫描** | JD 生成 + 歧视词扫描 + 违法话术提示 | 工作量小、合规价值大、销售演示效果好 |
| **入转调离 - 时间轴引擎** | 入职/转正/离职提醒 + 材料清单与催收看板（规则驱动，非 AI） | 用最低成本证明「流程不漏」的价值 |
| **人力报表 - 招聘漏斗 + 周报** | 日/周自动推送、固定指标口径 | 汇报场景刚需，老板满意 |
| **Agent 底座（最小集）** | 任务规划落库 + 工具注册 + HITL 闸门 + 权限校验 + PII 脱敏 + Trace | 不做底座等于盖空中楼阁 |
| **集成** | 飞书/钉钉消息 + 邮件 + 1 家 ATS（或 CSV 导入）+ 知识库上传 | 先打通一条线，不要贪多 |

**一期明确不做**：
- 面试视频分析、AI 自动面试
- 自动发 Offer、自动改薪资
- 候选人端自助门户
- 移动 App（先 H5）
- 多 Agent 协同（先用单 Agent + 固定工具集）
- 自定义编排的市场/分享功能（只做内部创建）
- 私有化部署（先 SaaS 验证产品）

### 6.2 一期验收指标（Go / No-Go）

| 指标 | 门槛 | 不达标怎么办 |
|---|---|---|
| 简历打分与 HR 判断 Top10 重合率 | ≥ 70% | 不放大推广，回到打分维度调参 |
| 员工自助 Top50 问题解决率 | ≥ 60% | 补知识库 + 加澄清追问 |
| 越权访问 / PII 泄漏 | 0 次 | 立即停止上线，安全返工 |
| 高风险动作未审核执行 | 0 次 | 同上 |
| HR 日活使用率（试点客户） | ≥ 60% | 说明产品没进工作流，重新做场景访谈 |
| 单任务平均成本 | ≤ 目标值（见成本章） | 优化模型路由与上下文 |

### 6.3 路线图

| 阶段 | 时间 | 目标 | 关键交付 |
|---|---|---|---|
| **阶段 1（一期 MVP）** | 第 1～16 周 | 一个客户、两个 Agent 跑通闭环 | 员工自助 + 简历筛选 + 底座 + 飞书集成 |
| **阶段 2（Pilot）** | 第 17～26 周 | 3～5 家试点，验证留存与 ROI | 招聘全链路 + 报表中心 + 编排 v1 |
| **阶段 3（GA 商业化）** | 第 27～40 周 | 补齐合规、计费、多租户运营 | 入转调离全模块 + 权限中心 + 计费 + 审计 |
| **阶段 4（Scale）** | 第 41 周起 | 规模化、私有化、行业模板 | 私有化部署包 + 行业 JD 库 + 模型路由优化 |

### 6.4 关键假设与被否证的可能（必须写清）

| 假设 | 如果被否证 | 调整方向 |
|---|---|---|
| HR 愿意为「筛简历」付费 | 调查发现客户更痛的是「员工咨询」 | 把员工自助变成长尾引流品，简历筛选取代为主打 |
| 客户 ATS 有可用的 API | 大量客户是 Excel/自研 | 强化「导入导出 + 邮件解析」降级路径 |
| 打分能被 HR 接受 | HR 不信任 AI 排序 | 改为「只给标签不给分」，把 AI 降级为信息整理者 |
| 客户能提供结构化知识库 | 文档散乱、过期严重 | 增加「知识库治理服务」作为付费前置交付 |
