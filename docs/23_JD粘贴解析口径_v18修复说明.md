## 1 · 这一版修的是什么

v17 把「编号残留、词被劈开、多条挤成一坨、任职要求混进职责」四件事修掉了。
但 v17 的**多断点**场景没被测到 —— 真实硬换行 JD 的每一行都断在词中间，于是暴露出
一个更隐蔽、也更难被肉眼归因的问题：**解析器会往句子中间凭空插一个逗号。**

把同一份 JD 按真实排版（每行都在词中间断开）粘贴进去，v17 的输出是这样：

```
[1] 跟随业务团队对接B端客户，……，主动挖掘潜在业务痛点
[2] 结合大模型应用能力，……，预判方案实施效果，与边界          ← 凭空多了一个「，」
[3] 将客户业务痛点转化为AI应用需求，协同技术团队梳理方案，跟进项目落地
[4] 跟踪AI应用，上线后的业务指标，评估方案带来的业务价值，持续迭代场景方案   ← 同上
[5] 轮岗学习业务、产品、AI应用，相关知识，成长为懂客户业务、懂AI落地的复合型产品人才 ← 同上
[6] 学历背景：211或985本科，及以上，……，擅长，沟通倾听，……            ← 两处
[7] AI认知：了解大模型等AI应用，的能力与局限，理解AI应用落地基本逻辑       ← 同上
[9] 软性素质：学，习能力强，……                                    ← 同上
```

注意：**编号已经被剥掉了、条目也已经切开了** —— v17 的四处修复都在生效。
坏掉的只有标点：接缝处被塞进一个原文里不存在的「，」，把「断行」升级成了「病句」。
「学，习能力强」「本科，及以上」这种写法，正是使用者说的「不符合正常语序」。

## 2 · 根因：一条在中文里站不住的旧规则

`parseReqText()` 的断行合并有三条判据，其中一条是：

> ② 上一行是**带列表符号**的项、且没写完 → 补一个逗号再拼接。
> 例：`• 把模糊的用户场景` + `拆成能落地的产品方案`

这条规则来自**西文**排版直觉：英文换行会吞掉一个空格，拼接时要补回来。
但它在中文里推导出了两处错误：

1. **中文换行从不会吞掉标点。** 一句话在排版时被折断，标点仍在原文里。
   所以在接缝处补逗号 = **凭空造标点**，不是还原原文。
2. **`cur.marked` 一旦置位就不再复位。** 硬换行 JD 的第一行带「1.」→ `marked = true` →
   此后**每一行**都命中判据 ② → 整段被并成一坨，且**每个接缝都插一个逗号**。
   断点越多，插得越多。

换句话说：这不是「补错了位置」，是**「补」这个动作本身在中文里就不该发生**。

## 3 · 修法（一处）

```js
// 旧（v17）
if (!cnCont && !tailShort) {
  cur.text += RE_END_MID.test(cur.text) ? '' : (/[A-Za-z0-9]$/.test(cur.text) ? ' ' : '，');
}

// 新（v18）
if (!cnCont && !tailShort && !RE_END_MID.test(cur.text) && /[A-Za-z0-9]$/.test(cur.text)) {
  cur.text += ' ';   // 只有西文换行才真会吞掉空格
}
```

**中文接缝：一个标点都不补。** 西文接缝：补空格（保留原行为）。
合并这件事本身不变 —— `• 把模糊的用户场景` 仍然与下一行合成一条，
只是不再往中间塞一个逗号。

## 4 · 断言与反向验证

`tools/test_jd.js` 新增**第 11c 节共 10 条**断言，用例是「每一行都断在词中间」的原文：

- 逐条锁住接缝两侧的原文完整：`预判方案实施效果与边界` / `跟踪AI应用上线后的业务指标` /
  `AI应用相关知识` / `211或985本科及以上` / `擅长沟通倾听` / `学习能力强` / `AI应用的能力与局限`
- 一条**反向锁**：正文里不得出现 `效果，与边界`｜`应用，上线后`｜`学，习能力` 这类凭空标点

**反向验证**（把 v18 规则放回 v17 的旧写法）：**9 条断言同时变红**，
点名了全部被污染的句子；还原后 134/134、文件字节一致。

套件总数：**124 → 134**。

## 5 · 已知边界（未修，沿用 v17 结论）

原始 JD 自身**缺分号**时（`…金融专业优先2.业务沟通能力：…`，`优先` 与 `2.` 之间没有「；」），
编号切不开，会与上一条粘在一起。

**为什么不加规则**：仅凭「汉字 + 数字点 + 汉字」无法区分「条目编号」与「版本号 / 数值」
（`提升3.倍`、`第2.章`），放宽必然引入误切。**收益抵不上风险**，因此显式记为已知边界。

- `REQ_LIB_VER` **17 → 18**。该版本号是**懒触发**的：只在 `GET /api/bootstrap` 比对，

  评测数字与基线一致（一致率 96.7% / 漏筛 0%）。
