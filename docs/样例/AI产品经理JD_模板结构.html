AI 产品经理 · 岗位 JD 模板结构

用途：把「AI 产品经理 / AI 应用产品管培生 / 智能体产品经理」这类岗位的 JD 写作标准化 —— 职责 5 段 + 要求 7 段，配 {{占位符}}，填完即用。 来源：3 份真实在招 JD（B 端 AI 应用方向）反向提炼，逐模块可溯源（见 §1）。 用法：抄 §8 骨架 → 按 §9 占位符词典填入 → 过 §7 风格规范 → 用 §12 自检清单收尾。

1 · 这份模板从哪来

编号岗位写法形态对模板的贡献
Aai 产品经理（苏州 · 客户现场型）叙事体M0 开篇定位段：「不是…也不是…」的排他式定位、搭档分工、成长方向、应届生准入的 4 条硬条件
BAI 应用业务产品管培生（27 届）条目体 + 能力标签前缀R1–R5 的「标签式」写法（学历背景／业务沟通能力／AI 认知／产品思维／软性素质）；M5-B 轮岗成长条
CH261_JD（苏州 · 制造业 AI 应用 · 智能体/知识库）纯条目体M1–M5 五段职责骨架、R1–R5 要求骨架、R7 硬约束项（每周到岗天数／连续实习月数）

三份的共同骨架只有两条：

  • 职责是一条价值链 —— 调研 → 设计 → 落地 → 迭代 → 沉淀；
  • 要求是按「由硬到软」排序 —— 学历 → AI 认知 → 产品思维 → 沟通协作 → 软素质 → 加分 → 约束。

模板就是把这两条骨架固化成槽位。A 提供了「怎么开篇」，B 提供了「怎么排版要求」，C 提供了「职责与要求的标准条目」。

2 · 模板总览

区块模块必填条数这个模块负责讲清什么
头部H1–H4✅4 字段岗位名称／城市／类型／标签
开篇M0 角色定位○（强烈建议）1 段不是什么、本质是什么、和谁搭档、往哪成长
职责M1 需求洞察✅1–2走到业务一线，识别显性需求、挖掘潜在痛点
职责M2 方案设计✅1–2把业务问题转成可落地的 AI 方案与文档
职责M3 AI 落地✅1–2Agent 工作流／提示词／RAG 的设计与验收（AI 岗专有）
职责M4 协同迭代✅1–2跨团队澄清、跟进、复盘、盯指标
职责M5 沉淀成长○1资产沉淀（M5-A）或管培轮岗（M5-B）
要求R1 学历专业✅1学历 + 届别 + 对口专业
要求R2 AI 认知✅1懂能力与局限 —— AI 岗与普通产品岗的分水岭
要求R3 产品思维✅1拆解、抽象、把问题转成方案
要求R4 沟通协作✅1表达、倾听、客户视角、跨团队
要求R5 软性素质✅1只写可观测的素质
要求R6 加分项○2–4真实经历／技术手感／领域资产
要求R7 硬性约束○1到岗天数、实习时长、驻场要求

总量控制：职责 5–6 条，要求 5–7 条。超过 8 条，说明没做减法。

缺项怎么办：当用人方只给了岗位名（没给任职要求 / 加分项）时，按 §10 缺省填充策略处理 —— 可推导的自动补并标注依据，不可推导的一律留 {{占位符}}。

3 · 头部信息（H1–H4）

字段必填写法示例
H1 岗位名称✅「方向 + 性质/职级」，不超过 20 字AI 应用产品经理（校招/实习）
H2 工作城市✅城市；有驻场就写上苏州（客户现场高频办公、阶段性驻场）
H3 岗位类型✅全职／实习／管培校招 · 产品管培生
H4 标签○3–4 个，给招聘平台筛选用B 端产品 / 智能体 / RAG / 语义类 AI
标签不是装饰。它决定简历会不会被搜到 —— 从这几类里挑：业务形态（B 端／C 端／SaaS）、技术关键词（智能体／RAG／大模型／工作流）、岗位族（产品经理／解决方案／FDE）

4 · M0 开篇定位段（可选，但强烈建议加）

为什么要有：AI 产品经理是个被用滥的 title —— 招聘方不写清「是哪一种」，来的简历一半是纯 PRD、一半是纯算法。开篇段的作用是在候选人投递前就做一次自我筛选。

三段式结构（每段 1–3 句）：

段讲什么模板句式
① 排他式定位不是什么 → 是什么这个岗位不是 {{排除项1}}，也不是 {{排除项2}}。核心是在 {{场景}}，把 {{输入}} 转成 {{产出}}，并持续 {{闭环动作}}。
② 本质与边界本质 + 不要求什么 + 必须要什么这个岗位本质上是：{{本质定义}} —— 不要求 {{低要求}}，但需要 {{必需要求}}。
③ 搭档与成长和谁配合、各自侧重、往哪走你将与 {{搭档角色}} 搭档推进：你更偏 {{A 侧}}；TA 更偏 {{B 侧}}。后续成长方向：{{方向1}} / {{方向2}}。

口语化变体（校招热情版，用一个具体的人来勾人）：

你是不是那种人 —— {{工具1}}、{{工具2}}、{{工具3}} 一个不落，天天琢磨"这玩意儿还能怎么用"？看到 {{现象}} 会忍不住想"这要是我来做，会做得更好"。那我们在等你。

别写：「我们提供有竞争力的薪酬和广阔的发展空间」—— 这类话占位置不传递信息。

5 · 岗位职责模板（M1–M5）

每条必须含 动作 + 对象 + 结果/目的 三要素。默认每模块 1 条；岗位范围大就拆 2 条。

M1 需求洞察　必填 · 1–2 条

  • 要点：对接 {{对象}} → 参与 {{调研动作}} → 理解 {{业务流程}} → 识别 {{显性需求}} → 挖掘 {{潜在痛点}}
  • 模板句：
跟随/对接 {{业务团队 / 客户}}，参与 {{业务访谈 / 现场走访 / 用户调研}}，理解 {{业务流程}}，识别显性需求并主动挖掘潜在 {{痛点}}。
  • 动词库：跟随、对接、参与、走访、调研、识别、挖掘
  • 占位示例：对象=B 端客户 / 制造业产线负责人；调研动作=业务访谈 / 车间走访；痛点=业务痛点 / 效率瓶颈

M2 方案设计　必填 · 1–2 条

  • 要点：判断可行性 → 设计落地思路 → 预判效果与边界 → 转化为需求 → 输出 PRD/原型
  • 模板句：
结合 {{大模型 / Agent}} 应用能力，判断 {{客户痛点}} 能否被解决，设计初步落地思路并预判 {{实施效果与边界}}；将 {{业务问题}} 转化为 {{可落地的 AI 应用需求}}，输出 {{PRD / 原型 / 需求文档}}。
  • 动词库：判断、设计、预判、拆解、转化、梳理、输出
  • 占位示例：输出物=PRD / 原型 / 需求文档 / 场景用例

M3 AI 落地　必填 · 1–2 条 ★ AI 岗专有

  • 要点：智能体工作流 → 提示词策略 → RAG 知识库 → 模型/工具选型 → 效果验收 → badcase 归因
  • 模板句：
参与 {{智能体工作流 / 提示词策略 / RAG 知识库场景}} 的设计与调优，负责 AI 功能的 {{效果验收 / badcase 归因 / 用户反馈分析}}，持续提升 {{回答准确率 / 任务完成率}}。
  • 动词库：参与、设计、调优、验收、归因、分析、沉淀
  • 提示：这一条是让候选人判断"这是不是我要的岗"的关键。写「参与调优」还是写「负责验收」，直接决定来的是产品苗子还是调参选手 —— 想清楚要哪种。

M4 协同与迭代　必填 · 1–2 条

  • 要点：跨团队澄清 → 迭代跟进 → 测试验收 → 上线复盘 → 跟踪业务指标
  • 模板句：
协同 {{产品 / 研发 / 算法 / 实施}} 团队完成需求澄清与迭代跟进，推动 {{方案落地}}；跟踪上线后的 {{业务指标}}，评估 {{方案价值}} 并持续迭代场景方案。
  • 动词库：协同、澄清、跟进、推动、验收、复盘、跟踪、评估

M5 沉淀与成长　可选 · 1 条（二选一或并存）

M5-A 资产沉淀（通用岗适用）

持续沉淀 {{行业案例 / 功能清单 / 竞品分析 / 产品模板}}，提升团队 {{交付效率}}。

M5-B 轮岗成长（管培生专属）

轮岗学习 {{业务 / 产品 / AI 应用}} 相关知识，成长为 {{懂客户业务、懂 AI 落地}} 的复合型产品人才。

6 · 任职要求模板（R1–R7）

两种写法，二选一： - 裸条式（岗位 C）：直接 1. 2. 3. 列出 —— 简洁，适合要求本身就短的岗位。 - 标签式（岗位 B）：每条以 {{能力类别}}： 开头 —— 可读性明显更好，推荐。 无论哪种，排序都由硬到软：学历 → AI 认知 → 产品思维 → 沟通协作 → 软素质。

R1 学历与专业　必填

  • 要点：学历门槛 + 届别 + 对口专业（3 类左右）
  • 模板句：
{{学历要求}}，{{届别}}；{{专业A}}、{{专业B}}、{{专业C}} 等相关专业优先。
  • 标签式：学历背景：…
  • 占位示例：学历=211/985 本科及以上 / 本科及以上；届别=2027 届应届毕业生 / 2026、2027 届优先；专业=计算机、软件工程、信息管理、工业工程、金融

R2 AI 认知　必填 ★ 分水岭条目

  • 要点：懂能力与局限 + 理解落地逻辑 + 真兴趣（不是跟风）
  • 模板句：
了解 {{大模型 / 智能体 / RAG 知识库}} 的能力与局限，理解 AI 应用落地的基本逻辑；对 {{方向}} 有明确兴趣，不是跟风。
  • 标签式：AI 认知：…
  • 热情版变体（校招）：见 §4 口语化变体。
  • 提示：只写「对 AI 有热情」是废话；要落到 "能说出能力边界" 这个可验证的点上。

R3 产品思维　必填

  • 要点：需求拆解 + 归纳抽象 + 能转成可落地方案
  • 模板句：
具备良好的 {{需求拆解}}、{{归纳抽象}} 能力，能把 {{业务问题}} 转化为 {{可落地方案}}；有 {{PRD / 原型 / 数据分析}} 经验者优先。
  • 标签式：产品思维：…

R4 沟通与协作　必填

  • 要点：表达清晰 + 会倾听 + 客户视角 + 能跨团队推动小任务
  • 模板句：
逻辑表达清晰，擅长 {{沟通倾听}}，能快速理解 {{陌生行业业务}}，具备 {{客户视角}}；善于 {{跨团队协作}}，能独立推动明确的小任务。
  • 标签式：业务沟通能力：…

R5 软性素质　必填

  • 要点：学习力、自驱、抗压、接受出差/驻场 —— 全部写成可观测行为
  • 模板句：
{{学习能力}} 强，{{自驱力}} 足，能接受 {{业务外出 / 客户现场办公 / 阶段性驻场}}。
  • 标签式：软性素质：…
  • ❗禁用词：有责任心、有团队精神、吃苦耐劳、抗压能力强。

替换写法人话版：扛得住事 / 愿意扎进真实用户场景 / 能接受高频客户现场办公。

R6 加分项　可选 · 2–4 条

从三类里挑，一条一类，不重复堆料：

类别写法
真实经历有 {{真实项目 / 实习闭链}} 经验，而不只是 {{课程 / 比赛 / 论文}}
技术手感懂点技术，能与工程对话；有自己的 Side Project；熟练使用 {{AI 工具}}
领域资产有 {{行业案例 / 竞品分析 / 方法论沉淀 / 数据分析}} 经验
判断力对 {{Agent 能力边界}} 有自己的判断

强化写法（岗位 A 的做法，值得抄）：

能讲清自己亲自做了什么、第一版做了什么 / 没做了什么。

这一句能筛掉大部分「参与过但说不清」的简历。

R7 硬性约束　可选（实习岗建议必填）

  • 要点：每周到岗天数 / 连续实习月数 / 城市与驻场
  • 模板句：
{{每周到岗 X 天}} 及以上，连续实习 {{X 个月}} 及以上优先；{{城市}} 现场办公 / 阶段性驻场。
  • ❗位置：永远放最后一条 —— 放前面会在第一屏劝退，而它其实不是硬淘汰项。

7 · 表述风格规范

维度要求
句式一条一句，动宾开头（职责）／「具备·了解·能」开头（要求）；不写主语，不写"我们希望你…"
长度25–50 字/条；超 60 字就拆两条
标点段内分句用 ；，整条收尾用 。；不用 、 堆 4 个以上并列
信息密度每条必须能指出 动作 + 对象 + 结果；缺任一要素就是废话
层级靠「模块小标题 + 能力标签」表达，不靠四级标题（★★★ 加粗满天飞反而没重点）
数字落地届别、学历、天数、月数、城市写实数，不写「若干」「一定」
术语一致同一个概念全文用同一个词：智能体≠Agent≠AI 助手 混用会显得没想清楚
可验证性任何要求都要能被一场面试验证。"有责任心"验证不了 → 换"扛得住事、能接受客户现场"

动词库（职责用）：跟随 · 对接 · 参与 · 走访 · 调研 · 识别 · 挖掘 · 判断 · 设计 · 预判 · 拆解 · 转化 · 梳理 · 输出 · 调优 · 验收 · 归因 · 协同 · 澄清 · 跟进 · 推动 · 复盘 · 跟踪 · 评估 · 沉淀 · 轮岗

动词库（要求用）：具备 · 了解 · 理解 · 能 · 擅长 · 善于 · 有…经验 · …优先

10 · 缺省填充策略（没提供任职要求 / 加分项时怎么办）

结论先给：能推导的自动补并标注依据，不能推导的一律留占位 —— 绝不编。

10.1 先分清「可推导」与「不可推导」

类别判断标准处理方式
可推导由「岗位名称 + 职能族 + 行业 + 岗位层级」必然成立的通用表述自动补，并标明依据来自哪一层
不可推导属于这家公司的具体事实：薪资、编制、汇报线、工作地点、到岗时间、特殊资质、证照一律留 {{占位符}}，一个都不猜

判断口诀：写出来之后，换一家公司还成立吗？ 成立 → 可推导；不成立 → 那是事实，必须问。

10.2 五层填充阶梯（自上而下，命中即止）

层级来源举例
L1你给的原文你贴的「27 届，专业不限」→ 直接落 R1，不改写
L2岗位名称 → 职能族「AI 产品经理」→ 产品职能族的核心技能词 / 对口专业 / 软素质素材
L3行业制造业 → 补赛道措辞（仅在职能识别不出时兜底）
L4岗位层级管培生 / 实习 / 应届 → 「工作经验」维度改成「无需经验 + 1–2 段对口实习」
L5通用兜底 + 显式标注以上都无依据 → 写最确定的表述，并标 {{待确认}}

为什么 L2 必须优先于 L3：行业只决定「公司在哪个赛道」，不决定「这个岗位要什么技能」。同属互联网，后端工程师和 AI 产品经理的技能毫无交集 —— 按行业补位，就会补出「AI 产品经理要熟悉 Java / Spring Boot」。这是本项目踩过的真实坑。

10.3 逐模块默认写法（没提供时我写什么）

岗位职责（M1–M5） —— 职责不编造业务细节，用职能族通用动作句式：

模块没提供时的默认写法依据
M1 需求洞察「跟随/对接 {{对象}}，参与业务访谈与现场调研，理解业务流程，识别显性需求并挖掘潜在痛点」职能族通用动作（L2），{{对象}} 留占位
M2 方案设计「结合大模型 / Agent 能力判断问题可否解决，设计落地思路并预判边界；输出 PRD / 原型 / 场景用例」职能族（L2）
M3 AI 落地「参与智能体工作流 / 提示词策略 / RAG 知识库的设计与调优，负责 AI 功能验收与 badcase 归因」L2；只有 AI 类职能族才给这条
M4 协同迭代「协同产品 / 研发 / 算法团队完成需求澄清与迭代跟进，跟踪上线后业务指标并持续迭代」通用（L5）
M5 沉淀成长「持续沉淀行业案例、功能清单与竞品分析，提升团队交付效率」；管培生换「轮岗学习业务 / 产品 / AI，成长为复合型产品人才」L4（层级决定走哪条）

任职要求（R1–R7） —— 要求全部可推导，是自动补的主力：

模块没提供时的默认写法依据
R1 学历专业「本科及以上学历，{{专业}} 等相关专业优先」；学历不限时写「学历不限，以实际能力与项目经验为主要评估依据」L2 职能族 majors
R2 AI 认知「了解大模型与智能体的能力与局限，理解 AI 应用落地基本逻辑；对 {{方向}} 有明确兴趣，不是跟风」L2；非 AI 岗不写
R3 产品思维「具备良好的需求拆解与归纳抽象能力，能把业务问题转化为可落地方案」L2
R4 沟通协作「逻辑表达清晰，擅长沟通倾听，能快速理解陌生行业业务，具备客户视角；善于跨团队协作」L2 / L5
R5 软性素质「学习能力强，自驱力足，能接受业务外出与客户现场办公」L2 职能族 soft 素材
R6 加分项「有 {{方向}} 相关实习或项目经历者优先；能讲清自己亲自做了什么、第一版做了什么 / 没做了什么」L2 职能族 nice
R7 硬约束不生成 —— 到岗天数、实习月数、驻场要求属公司事实，一律留 {{占位符}}✗ 不可推导

10.4 三条红线

  1. 不编硬数字 —— 薪资、编制、到岗时间、汇报线、地点。这类「补一个看起来合理的」是最容易出事的地方，一旦写进 JD 就是对外承诺。
  2. 空缺不沉默 —— 没依据的项宁可写 {{待确认}}，也别用默认值悄悄糊过去。默认值最大的危害不是写错，是让空缺看起来像已确认。
  3. 加分项不为凑数而写 —— 宁可只写「如有相关经历欢迎在面试中说明」，也不硬凑四条。凑出来的加分项会把不匹配的人吸进来。

10.5 外部信息来源渠道（需要补事实时才用）

渠道能拿到什么可信度用法
公司自有数据（岗位库、在职员工画像、历史招聘记录）内部一致的级别与口径★★★优先；能定 R1 / R2 的档位
用人经理 / 内部访谈上面所有渠道拿不到的★★★终裁；不可推导项只能问出来

11 · 套用示例（模板填一版）

下面是把模板套到「27 届校招 · Agent 产品经理」上的结果，用来对照格式。内容只是示例，重点是槽位怎么落。

Agent 产品经理（北京 · 27 届校招）

标签：智能体 / B 端产品 / 大模型应用

〔开篇定位〕

这个岗位不是纯 PRD 岗，也不是纯算法岗。核心是在真实用户场景里，把模糊的需求转成可落地的 Agent 方案，并持续跟进使用反馈与版本迭代。

这个岗位本质上是：会思考、会干活的产品负责人 —— 不要求你懂训练模型，但需要你懂它的能力边界在哪。

你将与算法、工程团队并肩推进：你更偏场景定义与产品判断；TA 们更偏能力实现与工程落地。后续成长方向：AI 产品负责人 / 行业解决方案 / FDE。

〔岗位职责〕

  1. 跟着真实用户跑场景，参与需求访谈与现场观察，理解任务链路，识别显性需求并主动挖掘潜在痛点。
  2. 结合大模型与 Agent 能力，判断哪些问题值得用 AI 解、哪些解不了，设计落地路径并预判效果与边界；输出 PRD、原型与场景用例。
  3. 参与 Agent 工作流与提示词策略的设计与调优，负责 AI 功能的验收与 badcase 归因，持续提升任务完成率。
  4. 协同算法、工程团队完成需求澄清与迭代跟进，推动方案上线；跟踪上线后的使用数据，评估价值并持续迭代。
  5. 持续沉淀行业案例、功能清单与竞品分析，提升团队交付效率。

〔任职要求〕

  1. 学历背景：本科及以上，2027 届应届毕业生；专业不限，计算机、软件工程、工业工程等相关专业优先。
  2. AI 认知：了解大模型与智能体的能力与局限，理解 AI 应用落地基本逻辑；对 Agent 是真热爱，不是跟风。
  3. 产品思维：具备良好的需求拆解与归纳抽象能力，能把模糊的用户场景转化为可落地的产品方案。
  4. 业务沟通能力：逻辑表达清晰，擅长沟通倾听，具备用户视角与同理心；善于跨团队协作。
  5. 软性素质：学习能力强，自驱力足，好奇、主动、扛得住事，愿意扎进真实用户场景。
  6. 加分项：有 AI 产品实习经历；懂点技术，能和工程对话；有自己的 Side Project；对 Agent 的能力边界有自己的判断。
  7. 每周到岗 4 天及以上、连续实习 6 个月及以上优先。

12 · 写完自检清单

  • [ ] 职责条数在 5–6 条，要求条数在 5–7 条？超了没有？
  • [ ] 每一条都能指出 动作 + 对象 + 结果？有没有只有形容词的条目？
  • [ ] R2 AI 认知 是否落到了「能力边界」这种可验证的点上，而不是「对 AI 有热情」？
  • [ ] 有没有出现 禁用词（有责任心／有团队精神／吃苦耐劳／抗压能力强）？
  • [ ] 数字是否都是实数（届别、学历、天数、月数、城市）？
  • [ ] 术语是否全文统一（智能体 / Agent 只留一个）？
  • [ ] 加了 M0 开篇定位段 吗？没加的话，候选人靠什么判断这是哪种 AI 产品岗？
  • [ ] R7 硬约束 是不是放在了最后一条？
  • [ ] 自动补出来的内容，标了依据吗（职能族 / 行业 / 层级 / 通用）？没标的会被当成已确认事实。
  • [ ] 有没有把不可推导项（薪资、地点、到岗时间）也顺手填了？那是在替公司做承诺。
