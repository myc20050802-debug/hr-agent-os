## 一、项目定位与目标形态

### 1.1 一句话定位

**一个可私有化部署的「HR 数字员工平台」**：HR 在系统里建立岗位库，AI Agent 承接**简历初筛、JD 生成、审批留痕、员工自助问答**四类高频工作；所有涉及判断的环节都给出**可追溯的证据**，所有涉及合规的环节都由**确定性代码**兜底。

### 1.2 目标形态（已与你确认）

| 维度 | 结论 | 说明 |
|---|---|---|
| 产品形态 | **单租户 · 可私有化部署的产品** | 不背多租户 SaaS 与计费的包袱 |
| 使用目的 | **求职作品集 / 面试演示** | 结论：技术纵深与「讲得清取舍」优先于运营完备度 |
| 身份体系 | **自建账号 + RBAC** | 不接企业 SSO，不做组织架构同步 |
| 部署方式 | 单机 / 单容器，数据不出本机（私有化） | 与「简历属敏感个人信息」的定位自洽 |

**为什么这个组合是自洽的**：作品集要的是「能被追问的深度」，不是「能扛多少租户」。因此把工程量投在**可信（身份/权限/审计）、可控（确定性规则边界）、可讲（架构分层与取舍）**三件事上，而不是多租户计费。

### 1.3 与现有资产的关系

| 现有资产 | 现状 | 在目标形态里的角色 |
|---|---|---|
| `平台原型/index.html` | ✅ 已实现：单文件 366KB、23 页、零依赖、双击即开 | **演示主入口**（离线可演示，不怕现场没网） |
| `server/` 零依赖后端 | ✅ 已实现：Node 22 原生 http + `node:sqlite`、13 张表、真写库/真闸门/真审计 | **演进基座**（保留其「零依赖可交付」的卖点，逐步换骨架） |
| `shared/req-lib.js` | ✅ 已实现：30 职能族 / 242 句职责 / 18 类行业词库，前后端唯一来源 | **核心资产**，产品差异化所在（详见 §4.2） |
| 双模式回归测试 | ✅ 已实现：离线 / 在线各 23 页 + 16 项，0 错误 | **质量证据**，面试可直接演示 |

## 二、用户、场景与目标

### 2.1 用户角色

| 角色 | 核心诉求 | 当前权限诉求 |
|---|---|---|
| **HRD / 招聘负责人** | 看清全盘、控风险、要审批权 | 全量读 + 审批 + 配置 |
| **招聘专员** | 快：少翻简历、少写 JD | 岗位维护 + 筛选台 + 候选人库 |
| **HRBP** | 掌握所支持团队的人员情况 | 本部门行级读 |
| **员工** | 自助查年假、社保、开证明 | **仅本人数据**（越权一律拒答） |
| **系统管理员** | 账号、权限、审计 | 用户与角色管理 |
| **数据保护负责人**（新增角色建议） | 谁看过敏感数据、留存多久 | 只读审计（详见 §9-④） |

### 2.2 As-Is（真实的一天）→ To-Be

| 痛点（As-Is） | 量化 | To-Be |
|---|---|---|
| 翻 80 份简历要 3–4 小时 | **设计目标：初筛人效 +70%**（未实测） | Agent 按「规则门槛 → 打分 → 证据」跑完，人只审闸门 |
| 被员工问社保/年假反复打断 | 20 次/天 | 员工自助，越权明确拒答并留痕 |
| 每月手工拼周报 ~4 小时 | **设计目标：4 小时 → 5 分钟**（未实测） | 报表与问数直连业务库 |
| JD 靠抄旧模板，条款带歧视风险 | 风险不可控 | 合规扫描按法条命中并**阻止发布** |

> **口径提醒**：上表右列凡标「设计目标」者均为**未实测值**，面试时应说「我设定的目标是 X，验证方式是 Y」，不要当成已达成结果。

### 2.3 产品原则（这四条决定了后面所有取舍）

1. **能用规则就别用模型** —— 年限、学历这类硬门槛由代码判定，**0 token**，结果可复现。
2. **物理剔除 > 提示词请求** —— 反歧视不是「请求模型别看性别」，而是**让模型根本拿不到**该字段。
3. **AI 的判断必须带证据** —— 每一条打分都要能指回原文片段，否则不可信。
4. **演示态与真实态结论同源** —— 离线模式的合规扫描也是真扫，不写死结论。

## 三、范围与非目标

### 3.1 本期范围（In Scope）

1. **岗位库与 JD 生成**（含合规扫描）✅ 已有，待打磨
2. **简历筛选 Agent**（规则门槛 → 打分 → 证据 → 人工闸门）

4. **员工自助问答**（HR 业务库查询 + 知识库检索 + 拒答转人工）
5. **身份认证与 RBAC**（本期最大新增，见 §6-M1）
6. **报表与问数**（现状为 mock，需接真查询）
7. **数据治理**（候选人授权、留存期、删除权）

### 3.2 非目标（Out of Scope，**明确不做**）

| 不做 | 理由 |
|---|---|
| 多租户 SaaS 与订阅计费 | 与「求职作品集」定位不符，且会稀释工程量 |
| 薪酬 / 考勤 / 绩效 / 社保代办等全 HRMS 模块 | 那是另一条产品线（对标 Frappe HR / OrangeHRM），本产品聚焦「招聘 + 自助」 |
| 自动发 Offer、自动拒信 | 高风险决策必须有人在场，产品原则不容许 |
| 简历爬虫 / 与外部 ATS 双向同步 | 合规与工程量双重不可控 |
| 生产级 K8s 编排与 SLA 承诺 | 本期交付到「单容器可部署 + 可观测」为止 |

> **为什么非目标要写死**：B 端产品的死法通常不是做得不对，而是做得太多。这一节同时是面试里最容易被追问的点——「你为什么不都做」比「你做了什么」更能看出判断力。

### 4.2 核心资产：岗位与 JD 的确定性生成

这是本产品**最不可替代**的部分，也是面试最值得展开的技术亮点：

- **职能族优先、行业兜底**：30 个职能族（技术/产品/设计/数据/运营/市场/销售/实施交付/HR/财务/风控合规/供应链/生产/工程设备/工艺/质量/医疗/客服/零售门店/行政/法务合规/教育培训/建筑工程/传媒内容/物流运输/酒店餐饮/物业安保/医药健康/游戏/能源电力）。
  - 解决的真实 bug：「互联网行业的 AI 产品经理被补上 Java」——根因是把「行业」当成「职能」。
- **一识别词只属一族**：族的分界按「这个人每天做什么」划，不按行业或公司部门划。
- **职责子方向择优**：242 句职责池带子方向标签，`pickDuties()` 按岗位名择优取 6 条 → **同族不同岗不再一字不差**，且纯规则、可复现、0 token。
- **行业语境词接回**：17 个行业各有「指标 + 行话」口径句（如「以 DAU、留存与转化漏斗为核心指标，结合埋点与 A/B 实验验证迭代效果」），拼入前做 LCS + bigram 双重去重。
- **版本自愈**：`REQ_LIB_VER` + `jobs.jd_ver`，启动时自动重算历史 JD，老脏数据不用手工洗。

> 面试价值：这一段能同时回答「你怎么处理幻觉」「怎么保证可复现」「规则和模型怎么分工」三个高频问题。

### 5.3 LLM 应用平台方向（用于定架构分层）

| 项目 | 定位 | 借鉴点 |

| RAGFlow | 深度文档理解 RAG | **多路召回 + 重排序**；复杂文档格式解析 |
| FastGPT | 知识库问答 | 混合检索 + 结果重排；PG + MongoDB 存储组合 |

> **本节的架构启示（已吸收进 docs/08）**：
> ① **适配器模式**隔离模型供应商 —— 换模型不改业务代码；
> ② **分层要按「变化频率」切**：模型、检索、规则三者的变化频率完全不同，不该混在一层；
> ③ **RAG 与规则引擎是并列的能力**，不是「RAG 取代规则」；
> ④ 企业能力的落点是 **SSO / RBAC / 审计日志**（Dify 企业版清单与 OrangeHRM 安全三件套相互印证）。

### 5.4 我们与对标的差异（面试必答）

> 主流开源项目要么偏**求职者侧**（career-ops、ai-job-search），要么偏**简历解析工具**（Resume-Matcher、hiring-agent），要么偏**全 HRMS 套件**（Frappe HR、OrangeHRM）。
> **我们的位置是它们之间的空档**：**HR 侧、以「岗位库驱动的确定性生成 + 可信 Agent 流程」为核心**——不是简历解析器，也不是 HR 大套件。
> **并且已有别人没有的东西**：30 职能族 / 242 句职责 / 18 类行业词库这套**跨行业岗位语义资产**，以及**双模式（离线可演示 / 在线真跑）**的交付形态。

| 项 | 内容 |
|---|---|

| 对标依据 | `hiring-agent` 的双后端打分、`resume-job-matcher` 的「分数带证据」 |

## 八、风险与依赖

| 风险 | 影响 | 应对 |

| **技术栈迁移成本**（现有零依赖 → 生产栈） | 高 | 保留现有 PoC 为「可运行证据」不删；用**分层**把规则引擎先抽成独立包（语言无关的纯函数 + 契约测试），迁移期间两套并存 |

## 十、验收口径（整体）

| 维度 | 验收标准 |
|---|---|
| **可信** | 无会话 → 401；越权 → 403 且留痕；审计只插不改；敏感字段加密存储 |
| **可控** | 硬门槛 0 token 且可复现；模型失败自动降级；每条 AI 判断可回溯证据 |
| **可讲** | 架构分层清晰、关键取舍有对标依据、能区分「已实现 / 设计目标 / 未定」 |
| **可演** | 断网可演示；5 分钟无卡点跑完主链路；离线 / 在线结论同源 |
| **可验** | 双模式回归全绿；评测集有基线且低于阈值阻断合并 |
