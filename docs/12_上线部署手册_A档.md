# HR-Agent OS · A 档上线手册

> 目标：**给别人一个链接，他能登录、能把主流程点完一遍，并且演示数据是稳定的。**
> 不管到的事：迁移 PostgreSQL、多租户隔离、真实简历解析 —— 那些是 B/C 档，写在 `docs/11` 里。
>
> 编写日期 2026-09-30 · 实测环境 Windows 11 + Node 22.22.2 + Git Bash。
> 手册里每条命令都标注了 **【实测】** 或 **【未实测】**；没标的默认没在本机跑过。

## 零、三十秒先看清楚现状：`npm run preflight`

发出链接之前先跑它。它是**只读**的（不改动任何数据），把「知道就不会错、不知道就一定会错」的那几条一次性查完：

```bash
npm run preflight
```

```

  ────────────────────────────────────────────────────────

  · 演示重置已开启（非生产环境，符合预期）
  ✓ 会话密钥来源：file（重启不掉线）
  ✓ 库文件存在：server/hr_agent.db（416 KB）
  ✓ 数据目录可写
  ⚠ 库文件在代码目录内：容器/重建部署会连数据一起丢掉
  ⚠ 9 个账号仍在使用演示口令「Demo@2026」：本机演示是预期状态
  ✓ 最近备份 hr_agent_20260930-091606.db（刚刚）· 共 1 份
  · 规则模式：未配 LLM_API_URL，打分与润色全走确定性规则
  ────────────────────────────────────────────────────────
```

退出码 `0` = 没有阻断项可以发链接；`1` = 有阻断项，处理完再发。
`⚠` 不阻断上线，但每一条都值得在「正式对外」之前处理掉。

### 每个检查项在防什么

| 检查项 | 它防的事故 | 处理动作 |
|---|---|---|
| 配置校验 | 生产环境配错就直接启动起来 | 按报错提示补 `.env` |
| COOKIE_SECURE × 访问协议 | 「登录成功，下一秒又回到登录页」 | HTTPS 就设 `1`，HTTP 必须留空 |
| 重置开关 | 公网上留着一个清库按钮 | 见 §4.3 |
| 会话密钥来源 | 重启一次所有人被登出 | 配 `SESSION_SECRET_FILE` 指向持久目录 |
| 库文件路径 | 容器重建连数据一起丢 | `DB_PATH` 指向挂载卷 |
| 演示口令 | 谁都能用 `Demo@2026` 登录 | 见 §4.1 |
| 备份 | 库是唯一副本，误删就没了 | `npm run backup` |

> 本机演示专属的两条 **`⚠` 是预期状态**：库在代码目录里（本地单实例跑）、共享演示口令（文档里就是这么写的）。
> 一旦监听地址离开 `127.0.0.1`，这两条会自动升级成阻断。

## 一、这次 A 档到底改了什么

`docs/11` 提的清单里有 5 项属于 A 档，现在**全部落地**，另有 1 项是落地过程中补出来的：

| 项 | 改之前 | 改之后 | 验证 |
|---|---|---|---|
| 配置 | 端口/库路径/密钥散落在代码里 | `server/.env`（示例见 `server/.env.example`），优先级：环境变量 > `.env` > 默认值 | `test_ops` 用 `DB_PATH` 起两个隔离实例 |
| Cookie / 环境约束 | `cookieSecure` 恒 false | `NODE_ENV=production` 时**强制** `COOKIE_SECURE=1`、`ALLOW_RESET` 默认关闭；不满足拒绝启动 | 配置校验用例 |
| 静态资源 | 500 KB 每次全量重传，全局 `no-store` | gzip + ETag 协商缓存 + `Vary`；HTML 用 `no-cache` | 500 KB → **166 KB**（实测压缩比 33.1%），304 命中无 body |
| 源码暴露 | `/src/app.js`、`/build.js` 可直接下载 | 一律 404；编码斜杠的目录穿越同样被拦 | `/src/app.js` → 404 **【实测】** |
| CORS | 允许头里残留已废弃的 `X-User` | 与实际认证方式对齐（含 `X-Session-Token`，不含 `X-User`） | 预检响应断言 |
| 重置 | `/api/reset` 对任何登录者开放 | 受 `ALLOW_RESET` 约束；`bootstrap.caps.reset` 下发到前端 → 按钮按能力显隐（**不是点了才 403**） | 开发放行 / 生产拒绝 **【实测】** |
| 备份 | 无（库是唯一副本且无备份手段） | `tools/backup.js`：`VACUUM INTO` 在线快照 + integrity 校验 + `--verify` / `--restore` + 保留策略 | 含「服务在跑时拒绝恢复」**【实测】** |
| **改密入口** | 无；上面那条「还在用演示口令」的结论**没有梯子** | 登录后右上角 🔑 走真实接口改密；待改密时按钮高亮 + 登录提示 | 8 项新增断言（见下） |

### 关于最后一行

写 `preflight` 时发现一个尴尬：它判定「9 个账号仍在用演示口令 → 阻断」，但整个界面里**没有任何地方能改密码**。
只服务端有 `/api/auth/change-password` 是不够的 —— 那意味着「你要自个儿去 curl」。

所以补了三步，并且每一步都进了回归（`tools/test_ops.js` 第五节，共 **48/48 通过**）：

```
✓ 改密前：初始口令仍可登录
✓ 当前密码不对 → 拒绝改密（否则会话被盗可以先改密永久占号）
✓ 新密码不足 8 位 → 拒绝
✓ 新旧密码相同 → 拒绝（否则「已改密」是假的）
✓ 改密成功，并返回被吊销的会话数
✓ 改密后旧口令立即失效
✓ 新口令可以登录
✓ 登录响应里的「待改密」标记已清零（preflight 的判定依据）
```

最后一条是关键：**改完了要让 `preflight` 自己说通过了**，而不是让人记得「我改过了」。

## 二、三条发布路径，挑一条走

### 路线 1 · cloudflared（最快，适合「现在就要给链接」）

```bash
# 1) 先把服务跑起来
npm run dev                      # 幂等：已在跑就不重复启动；库不存在会自动建并灌种子

# 2) 另开一个终端，拿公网 HTTPS 地址（10 秒左右）
cloudflared tunnel --url http://127.0.0.1:8788
# → 输出形如 https://xxxx-yyyy.trycloudflare.com
```

- 顺带解决了 HTTPS 和边缘 gzip，本机不用配任何 TLS。**【未实测】**（本机没装 cloudflared）
- 地址每次重启都变，适合临时分享；要固定域名得注册 named tunnel。
- ⚠️ 这一步之后你的实例就**对外可达**了 —— §4 的 4 件事必须做完。

### 路线 2 · 局域网 IP（同一 WiFi / 公司内网，无公网暴露）

```bash
cp server/.env.example server/.env   # server/.env 已在 .gitignore 里，不会被提交
```

编辑 `server/.env`：

```ini
HOST=0.0.0.0
PORT=8788
ALLOW_RESET=0
```

然后别人访问 `http://<你的内网IP>:8788`。**【未实测】**
同网段是明文 HTTP，不要在公共 WiFi / 展会网络里这么做。

### 路线 3 · 一台云服务器（长期可用）

`docs/11` 的 §A2 给了 Dockerfile + Caddyfile + systemd 三份片段（**均标注未实测**）。照抄之前先记住两件事：

1. **`DB_PATH` 必须指向挂载卷**，否则容器重建 = 数据全丢（这是 `preflight` 里那条 `⚠` 想说的事）；
2. **`SESSION_SECRET_FILE` 同样要指向挂载卷**，否则每次重启所有人被登出。

## 三、上线前必做的四件事

### 4.1 改掉演示口令

两种方式，任选：

**界面（逐个账号）**：登录 → 右上角 🔑 → 填当前密码 `Demo@2026` + 新密码两次 → 确认。改完该账号所有会话会被吊销，用新密码重新登录。

**命令行（一次改完 9 个账号）**：**【未实测】** —— 别在本机演示库上跑，跑完你就得重建种子了。

```bash
BASE=http://127.0.0.1:8788
OLD='Demo@2026'
NEW='换成你自己的强口令'

for U in U-000 U-001 U-002 U-003 U-004 U-005 U-006 U-007 U-008; do
  TOKEN=$(curl -s -X POST "$BASE/api/auth/login" -H 'Content-Type: application/json' \
          -d "{\"identifier\":\"$U\",\"password\":\"$OLD\"}" | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
  curl -s -X POST "$BASE/api/auth/change-password" \
       -H 'Content-Type: application/json' -H "X-Session-Token: $TOKEN" \
       -d "{\"oldPassword\":\"$OLD\",\"newPassword\":\"$NEW\"}"
  echo "  <- $U"
done
```

新密码约束：≥ 8 位、不能与当前密码相同，且必须给出正确的当前密码（服务端三重校验，见 `server/auth.js` 的 `changePassword`）。

### 4.2 备份

```bash
npm run backup            # 在线快照，不用停服  【实测】
npm run backup:list       # 看看有哪些
```

**【实测】** 一次真实备份的输出：

```
✓ 备份完成  backups\hr_agent_20260930-091606.db
   大小 376 KB · 岗位 21 · 候选人 79 · 用户 9 · 审计 9 · schema v7
   校验值 sha256 b6223632b5e2d3f3…（同目录 .json 清单）
```

注意它备份的是**单数**：把它挪到另一块盘（`--dir D:/hr-backup`），否则「备份」和「原件」一起没了等于没备份。

为什么用 `VACUUM INTO` 而不是复制文件：WAL 模式下复制 `-wal`/`-shm` 得到的是不一致快照，恢复后可能报 `database disk image is malformed`；`VACUUM INTO` 产出的是内部一致的完整库，而且**只读连接就能执行**，不阻塞正在写入的服务。

### 4.3 关掉重置

```ini
# server/.env
NODE_ENV=production     # 副作用：ALLOW_RESET 默认关闭 + 强制 COOKIE_SECURE=1
COOKIE_SECURE=1
```

生产实例上 `POST /api/reset` 返回 **403**，且文案说明是「开关关着」而不是「你没权限」（避免让人以为是权限配错了）；
命令行 `--reset` 同样被拒并直接退出 —— **开关只有一个，不存在「UI 关了但命令行还能清库」的缝**。

前端按钮不是「点了才报 403」：服务 `bootstrap` 下发 `caps.reset`，前端按这个能力决定按钮显隐 ——
没有这个能力就**根本看不见这个按钮**，而不是看见、点下去、弹一个「无权限」。

### 4.4 `COOKIE_SECURE` 必须与访问方式成对

| 访问入口 | 取值 | 取错的症状 |
|---|---|---|
| `https://…` | `1` | 不设：会话 Cookie 明文传输 |
| `http://…`（本机、内网） | 留空 / `0` | 设了：浏览器不发 Cookie → **登录成功却立刻回到登录页** |

这条不需要人记，`preflight` 第一项就会问。

## 六、出了问题先看这三处

| 症状 | 先看 |
|---|---|
| 登录成功立刻掉回登录页 | `COOKIE_SECURE` 与访问协议不配对（§4.4） |
| 别人打开很慢 | 确认 gzip 生效（验收清单 #3）；未压缩时首屏要传 500 KB |
| 数据没了 | `backups/` 里找最近的快照 → `node tools/backup.js --restore <file>`（**必须先停服**，`--force` 可跳过检查） |
| 「AM-挂了」但日志没报错 | 用 `npm run dev` 起的服务跨会话存活依赖 WMI；直接 `node server/server.js` 起的进程会随命令结束被回收 |

## 七、这段管子到这里为止 —— 下一截是什么

A 档做完，**它是可访问的，但还不是「每天有人用」的工具**。中间隔着三件具体的东西（都属 B 档，`docs/11` 有展开）：

1. **没有真实简历入口** —— 现在库里的 79 个候选人全是合成的（`synthesized=1`）。这是「演示」和「用」的分界线：真 HR 打开第一件事是导入自己的简历。
2. **没有接模型** —— 现在打分与润色全走确定性规则（这点本身是好的：离线可用、可回归、评测一致率 90%）。但真实简历的表达多样性会超出词库，`shared/req-lib.js` 的 30 个职能族撑不住所有写法。
3. **备份还是手动的** —— `npm run backup` 会用了，但没人天天记得跑。它需要一个定时任务 + 异地目录。

**再往后才是别的事务：换 PG、做多租户、过合规（`TENANT` 现在还是写死的 `T-001`）。**
在那之前先让它被人用起来 —— 顺序反了，就永远没有「用起来」的那一天。
